## 0. 怎么用这份文档

1. **Token 优先**。颜色、字体、圆角、尺寸、动效时长都定义在 §3.2。实现时不要写死具体值，引用变量名。
2. **配色方案与深浅色正交**。方案决定"外框气质"，深浅色决定明暗。二者组合出的变量值见 §3.2 的四张表。
3. **原文不属于我们**。网页和 PDF 的排版由对方决定，我们只叠加痕迹；可改的只有产品自己的外框。见 §2 原则一、二。
4. **改动流程**：先改本文件（加上 `index.html` 的可视示例），再改实现。

## 1. 产品与使用场景

MyZ Annotator 是一个本地优先的标注与阅读工具：用户在网页和 PDF 上划线、摘录、写批注，之后回到文库里重新翻看。Inbox 是新采集内容的处理队列；基础采集、队列动作和文库不依赖 AI。关键词、代表句、重复提醒和来源上下文是可解释的本地辅助信息，端侧语义模型属于后续实验。

**目标用户**：个人知识工作者与学习者本人。一边读一边记，几个月后还要翻出来用。

**两条主线动作**：

| 动作                         | 频率       | 对设计的要求                                 |
| ---------------------------- | ---------- | -------------------------------------------- |
| 采集（划线、摘录、截取）     | 一天很多次 | 快，出现在视线附近，不打断阅读，不遮挡上下文 |
| 回看（文库、Inbox、查看器、阅读器） | 一天几次   | 找得到；未处理内容可集中处理，已保留内容可长期回看 |

**由此推导的使用习惯**：

| 习惯                 | 对设计的要求                               |
| -------------------- | ------------------------------------------ |
| 选中一段马上就想划线 | 采集条在视线附近出现，一步到位             |
| 常在深夜或通勤路上读 | 深色和浅色都要完整可用                     |
| 一读就是半小时以上   | 长文用衬线体、纸色底、宽行距，界面退到后面 |
| PDF 占很大比例       | 原页不动，页码和图注要对得上               |
| 几个月后回来找一句话 | 记录能按来源与文中顺序还原                 |
| 既在电脑也在手机上   | 跨设备共用同一套视觉语言                   |

## 2. 设计原则

八条。每条后面是理由，用来判断新方案是否成立。

### 2.1 原页不重排

网页用网站自己的排版。PDF 用 pdf.js 画出的原页，划线是叠在页面坐标上的一个框。缩放只改整页大小，不改断行。

**Rationale** 产品承诺是"点开原文，还能看见那句话就在原处"。一旦重排，页码、分栏、图注、标注坐标全部失效。EPUB 可以重排，是因为它本身没有固定页，与 PDF 是两回事。

### 2.2 只统一属于我们的部分

采集条、弹窗、文库、PDF 阅读器的外框共用同一套 Token 与组件，深浅色跟随用户设置。原文本身不换字体。

**Rationale** 外框是我们的产品，原文是别人的。只统一能统一的，扩展、桌面、手机才能共用同一份代码。

### 2.3 划线是记录，不是装饰

五个高亮颜色是用户自己定的记录数据，换配色方案和深浅色都不改。品牌色只用于按钮、当前项和链接，不与划线抢颜色。

**Rationale** 用户可能已经用某个颜色标了很久，换主题改写颜色等于打乱他整理过的东西。采集条是临时的操作层，不跟随主题。

### 2.4 按阅读时长选字体

界面用系统无衬线字体。需要长时间阅读的内容用衬线体：西文 Newsreader，中文按界面语言选对应的 Noto Serif 地区版本。

**Rationale** 按钮看一眼就走，摘录会盯着读很久。西文和中文同一类气质，长文里插入英文不突兀；界面跟系统走，插件才不像贴上去的一层皮。

### 2.5 松紧看场景

采集条与 PDF 顶栏用紧凑 32，文库用常规 36，手机用触控 44。同一种组件只改高度，不改长相。

**Rationale** 采集是在别人的文字上面操作，按钮一大就挡内容；手机手指粗，按钮一小点不准。

### 2.6 默认不用阴影

层级用留白和一条细线建立。阴影只给真正浮起来的层：采集条、批注面板、弹窗、下拉、目录浮层。

**Rationale** 到处加阴影和大圆角会与网页本身抢层级，也让文库看着像数据管理工具。

### 2.7 一个动作一个词

同一个功能只用一个说法。代码里的内部叫法可以保留，但不能印在按钮上。

**Rationale** 用词不稳定，按钮、提示、空状态就无法复用。词表见 §5。

### 2.8 动效只解释变化

动效回答"它出现了""找到了"。正在读的文字保持在原位。

**Rationale** 划线和阅读都要求注意力集中，正文一动会被误认为页面在跳。切换深浅色只改颜色。

## 3. 基础

### 3.1 配色方案

默认 **米纸（paper）**，另提供 **冷灰（slate）**、**青瓷（celadon）**、**赭石（ochre）**，由用户在设置里选择。方案只改变产品外框，不改划线五色、语义色和组件尺寸。

| 方案                 | 定位                              | 亮底色    | 暗底色    |
| -------------------- | --------------------------------- | --------- | --------- |
| `paper` 米纸（默认） | 暖米 + 油墨蓝，长时间阅读不刺眼   | `#F5F4ED` | `#141413` |
| `slate` 冷灰         | 中性冷灰 + 靛蓝，接近系统默认观感 | `#F8FAFC` | `#0F172A` |
| `celadon` 青瓷       | 极浅青绿 + 深绿                   | `#F2F4EE` | `#101512` |
| `ochre` 赭石         | 暖沙 + 铁锈红，更旧的纸感         | `#F6F0E6` | `#17130F` |

实现方式：根元素上两个属性，`data-scheme="paper|slate|celadon|ochre"` 与 `data-theme="light|dark"`。

**规则**

- 语义色（警告、错误、成功、提示）只跟深浅色，不跟方案。
- 高亮五色属于记录数据，与方案、深浅色都无关。
- PDF 阅读器外框跟随方案与深浅色；PDF 页面本身永远是原件颜色。
- **固定深色的范围就三样**：网页采集条、点击已有划线弹出的紧凑三按钮高亮条、通知提示条（`--myz-overlay`）。完整批注浮层、PDF 阅读器 Inspector、设置页提示都跟随主题。固定深色组件内部统一用 `--myz-overlay-text` 做文字与聚焦色，`--myz-overlay-hover` 做悬停底（见 §4.7、§4.18）。
- 设置页里的行内状态文字（`.status-line`）跟随主题，不用固定深色；只有会浮起、可能压在任意内容上的通知才用 `--myz-overlay`。

| `--myz-accent` / `--myz-accent-hover` / `--myz-accent-text` / `--myz-on-accent` | 强调色（按钮填充）/ 悬停 / 当文字用的强调色 / 强调色上的文字 |
| `--myz-tag-bg` / `--myz-tag-fg`                                         | 标签底色 / 标签文字                                          |
| `--myz-control-bg` / `--myz-control-border`                             | 控件底色与边框，比所在容器抬高一档                           |
| `--myz-skeleton`                                                    | 加载占位                                                     |
| `--myz-well` / `--myz-well-chrome` / `--myz-well-border`                    | 阅读器页面外的底 / 顶栏与侧栏 / 边框                         |
| `--myz-well-text` / `--myz-well-muted`                                  | 阅读器外框正文 / 次要文字                                    |
| `--myz-well-control-bg` / `--myz-well-control-border`                   | 阅读器外框里的控件                                           |
| `--myz-shadow`                                                      | 浮层的投影，按方案与深浅色各一套（见 §3.7）                  |

**深色下怎么分层**：浅色模式里按钮靠一条边框就能与卡片分开；深色模式改用"抬高底色"——控件底色比所在容器亮一档，再加一条更清楚的边框。`--myz-control-bg` 与 `--myz-control-border` 就是为此存在，浅色深色各一套。

### 3.3 语义色

只跟深浅色，不跟配色方案。错误在任何方案下都是同一个色号。

| 语义 | Token                                             | light                             | dark                              | 用法                                 |

| 成功 | 4.99     | 7.55     |
| 提示 | 5.67     | 7.62     |
| 摘录 | 4.50     | 5.60     |

### 3.4 划线颜色

五色属于记录数据，存在记录里，换方案与深浅色都不改。

| Token      | 值        | 名称         |
| ---------- | --------- | ------------ |
| `--myz-mark-1` | `#b58900` | 琥珀（默认） |
| `--myz-mark-2` | `#ef476f` | 珊瑚         |
| `--myz-mark-3` | `#9f7aea` | 紫           |
| `--myz-mark-4` | `#38bdf8` | 天蓝         |
| `--myz-mark-5` | `#34d399` | 青绿         |
| `--myz-highlight-color` | 逐条内联，默认 `var(--myz-mark-1)` | 当前这条记录的颜色通道 |

**`--myz-highlight-color`** 不是主题色，而是"当前这条记录自己的颜色"：渲染一条划线/标注时把它内联到该元素上，规则里统一引用它。这样同一份规则能同时服务五色，且颜色永远来自记录数据而不是主题。

**三种样式怎么画**

| 样式             | 画法                                                                                 |
| ---------------- | ------------------------------------------------------------------------------------ |
| 涂色 paint       | `background: color-mix(in srgb, <色> 42%, transparent)`；圆角 3px，左右各 2px 内边距 |
| 下划线 underline | 不填底；线用实色，粗 2px，`text-underline-offset: 0.12em`                            |
| 波浪线 wavy      | 不填底；线用实色，粗 1.5px，`text-underline-offset: 0.16em`                          |

**PDF**：盖在渲染好的页面上，用图层透明度 35%，选中那条升到 55%。

**规则**

- 存储值始终是不透明十六进制；透明度只在渲染时加，数据不随主题变。
- 天蓝、青绿这类偏亮的颜色在浅色页面上可把透明度提到约 50%，其余维持 42%。
- 悬停与跳转反馈使用该记录自己的颜色，不用品牌色。

**Rationale** 用户划线是为了以后还能读，不是为了把句子涂掉。铺实色会压掉文字、行距和相邻内容；半透明让痕迹和文字并存。

### 3.5 字体与排版

**字体栈**

- 界面：`--myz-sans`（系统无衬线）
- 长文：`--myz-read` = `Newsreader, var(--myz-cjk), serif`
- 等宽：`--myz-mono` = JetBrains Mono

**中文按语言选地区版本**，只加载当前语言那一套。下表的地区版本是规范目标。

| 界面语言        | `--myz-cjk`       | 说明                  |
| --------------- | ------------- | --------------------- |
| `zh-CN` `zh-SG` | Noto Serif SC | 简体，默认            |
| `zh-TW`         | Noto Serif TC | 台湾正体              |
| `zh-HK` `zh-MO` | Noto Serif HK | 香港字形，TC 代替不了 |
| `ja`            | Noto Serif JP | 日文假名与日式汉字    |
| `ko`            | Noto Serif KR | 韩文                  |
| 其它            | Noto Serif SC | 默认                  |

**落地**：五个地区的 Noto Serif 均本地打包，按当前 UI 语言**只加载对应的一套**（`@myz/shared/fonts`，字重 400 / 600）。换语言只换中文字体文件，另一套不进内存。

判断顺序：用户在设置里选的语言 → `chrome.i18n.getUILanguage()` → `navigator.language`。宿主通过 `data-cjk` 落到 `--myz-cjk` / `--myz-sans`（§3.2）；内容层浮层只把 `data-cjk` 镜像到 Shadow 挂载点，不自行加载字体文件（Shadow 里的 `url()` 会相对宿主页解析），长文按系统衬线回退。

**字号层级（九级）**

| 层级            | 字号 / 字重 / 行高 | 字体 | 颜色                         |
| --------------- | ------------------ | ---- | ---------------------------- |
| 页面大标题      | 32 / 600 / 1.2     | 长文 | `--myz-text`                     |
| 区块标题        | 24 / 600 / 1.25    | 长文 | `--myz-text`                     |
| 小节标题        | 17 / 600 / 1.35    | 长文 | `--myz-text`                     |
| 导语            | 17 / 400 / 1.7     | 长文 | `--myz-muted`                    |
| 正文            | 15 / 400 / 1.7     | 长文 | `--myz-text`                     |
| 表格 / 紧凑正文 | 14 / 400 / 1.5     | 界面 | `--myz-text`                     |
| 说明文字        | 13 / 400 / 1.55    | 界面 | `--myz-muted`                    |
| 编号 / 辅助     | 12 / 500 / 1.4     | 界面 | `--myz-muted`                    |
| 标签 / 小标题   | 11 / 600 / 1.4     | 界面 | `--myz-muted` 或 `--myz-accent-text` |

**阅读字号五档**：15 / 16 / **18（默认）** / 20 / 22。

**组件到九级的映射**（新组件先在这里找，找不到再讨论加级）

| 层级 | 用在哪 |
| ---- | ------ |
| 页面大标题 | 文库 / 设置页的页面标题（`<h2>`），着陆页大标题 |
| 区块标题 | 卡片内区块、设置分组的大标题；查看器页标题 |
| 小节标题 | 设置分组标题、面板标题、记录卡里的正文小标题（如"划线/摘录"） |
| 导语 | 标题下的一句说明；面板/分组的 `--myz-muted` 引导语 |
| 正文 | 记录正文、批注正文、阅读区文字（配合五档字号） |
| 表格 / 紧凑正文 | 列表行、表单值、按钮文字上下文、卡片正文 |
| 说明文字 | 来源、时间、页数、字段提示（hint）、次要对齐信息 |
| 编号 / 辅助 | 组计数、`+N`、页码、筛选计数等靠右的辅助数字 |
| 标签 / 小标题 | 标签 chip、类型标签、分组小标题（配 `--myz-muted` 或 `--myz-accent-text`） |

**等宽（`--myz-mono`）只用三处**：代码块、PDF 页码、指纹与版本号。PDF 页码用 `--myz-mono` + `tabular-nums`，不用界面无衬线。

**Rationale** 同一层意思各页面自己挑字号会很快出现七八种相邻字号。定成九级之后，新页面只要说"这是小节标题"，答案就是确定的。映射表把"这个组件用哪级"从每次判断变成长表查询，相邻字号不会再各自漂移。

### 3.6 布局与间距

- 间距基准 4px，常用步进 4 / 8 / 12 / 16 / 20 / 24 / 32 / 40。
- 页面边距：桌面 40，窄屏 16。
- 阅读栏最宽 38em（对应 `--myz-read-measure`）。
- **固定宽度（不许各页各写）**：

| 区域 | 宽 | 说明 |
| ---- | -- | ---- |
| 文库来源侧栏 | 240–280（取 264） | 与设置侧栏同宽 |
| 设置侧栏 | 240 | `lg:w-60`，分组导航 |
| PDF 目录 / 标注停靠侧栏 | 240 | 内含两个分页签；标注行要放得下 |
| 浮动目录 §4.11 | 展开 200 / 收起 44 | 浮层，不占正文宽 |
| 批注浮层 §4.8 | 280 | 网页与 PDF 都是浮动 280 |
| 采集编辑弹窗 §4.8 | 320 | 样式 / 标签 / 调色盘 |
| 扩展弹窗 §4.21 | 360 | 系统面板 |

- 窗口窄于 **900px** 收成单栏；侧栏、设置侧栏、PDF 侧栏都改为抽屉（覆盖式，不压内容宽度）。断点用 900，不再用 1024。
- Inbox 桌面为「左侧栏 240 + 单栏队列」两栏：左栏是状态导航（待处理/稍后处理/已标记）与标签列表，标签项是拖拽投放目标（把队列记录拖上去即打标签）；窄于 **900** 时左栏收进抽屉，队列保持单栏，不引入横向滚动。
- 设置页是「侧栏 + 内容」两栏，窄于 900 时侧栏收进抽屉，内容单栏。

**PDF 布局**：目录 / 标注停靠侧栏 240 · 原页 1fr；批注 Inspector **浮动在原页上（280）**，不占独立列。

**设置只本地持久化**：配色方案、划线偏好等设置存在本地，不随 E2EE 同步；跨设备不保证设置一致，记录数据才同步。

**200% 缩放与窄屏重排**

- 页面放大到 200% 时：固定宽侧栏改为可收缩或抽屉，卡片/表单/PDF 顶栏不得横向溢出，长文本换行而不是撑破容器。
- 禁止用 `min-width` 写死整个页面；只有 PDF 原页舞台允许横向滚动。
- 字号用 rem 或 Token 值，不写死 px 让缩放失效；组件高度用 `--myz-hit-*`。

**Rationale** 分栏是为了同时看清两样东西——文库要并排"来源"与"记录"，PDF 要并排"目录/标注""原页""批注"。阅读栏限宽是为了每行别太长。固定宽度表把"侧栏到底多宽"从每页自行决定变成查表，避免 200/240/280/320 四种并存。

### 3.7 圆角与深度

| 圆角 | Token      | 用在哪                                         |
| ---- | ---------- | ---------------------------------------------- |
| 4    | `--myz-r-xs`   | 色块、条形、行内小标记                         |
| 6    | `--myz-r-sm`   | 标签、下拉选项                                 |
| 8    | `--myz-r`      | 按钮、输入框、图标按钮——所有能点的小控件       |
| 12   | `--myz-r-lg`   | 卡片、弹窗、下拉面板、目录浮层——所有装东西的面 |
| 胶囊 | `--myz-r-pill` | 只给浮在页面上的工具条和分段选择               |

判断法：控件比容器小一档。容器 12，里面的按钮 8；按钮 8，里面的标签 6。胶囊只用于工具条。

**深度**：默认平面。**只有真正浮在内容之上的层允许投影**，且只允许下面这一份清单：

| 允许投影 | 不允许投影（用边框/底色分层） |
| -------- | ----------------------------- |
| 采集条、紧凑高亮条（固定深色，见 §4.7） | 记录卡 `HighlightCard` |
| 批注浮层 / Inspector | 分组容器、设置分组卡 |
| 弹窗、下拉菜单、搜索建议 | 面板外壳、页面侧栏、设置侧栏 |
| 浮动目录 | PDF 舞台里的原页（原页是原件，用页面抬升表达，见 §4.22） |
| 通知提示条 | 按钮、输入框、标签、列表行 |

深色模式靠"抬高底色 + 更清楚的边框"分层，不靠加重阴影。违反本表的实现按 B 类差异处理。

`--myz-shadow` 按方案与深浅色各一套：

| 方案    | light                                | dark                              |
| ------- | ------------------------------------ | --------------------------------- |
| paper   | `0 14px 36px rgba(20, 20, 19, 0.12)` | `0 16px 40px rgba(0, 0, 0, 0.45)` |
| slate   | `0 16px 40px rgba(15, 23, 42, 0.18)` | `0 16px 40px rgba(0, 0, 0, 0.4)`  |
| celadon | `0 14px 36px rgba(18, 30, 22, 0.12)` | `0 16px 40px rgba(0, 0, 0, 0.45)` |
| ochre   | `0 14px 36px rgba(35, 26, 18, 0.14)` | `0 16px 40px rgba(0, 0, 0, 0.5)`  |

采集条的边界例外，用固定值（深色投影 + 浅色描边），见 §4.7。

### 3.8 动效

| Token            | 时长        | 用在哪                       |
| ---------------- | ----------- | ---------------------------- |
| `--myz-motion-fast`  | 120ms       | 悬停变色、聚焦光圈、按钮反馈 |
| `--myz-motion-med`   | 180ms，缓出 | 采集条与批注面板淡入、提示条 |
| `--myz-motion-panel` | 240ms       | 侧栏、抽屉、目录收合         |
| —                | 不动        | 正文与 PDF 页面内容          |

**组件到档位的映射**

| 组件 | 用哪档 | 动什么 |
| ---- | ------ | ------ |
| 按钮 / 图标按钮 / 链接 | fast 120ms | 底色、边框、文字色 |
| 输入框 / 下拉项 | fast 120ms | 边框、聚焦光圈 |
| 采集条、紧凑高亮条 | med 180ms 缓出 | 淡入（可带 ≤4px 位移） |
| 批注浮层 / Inspector | med 180ms 缓出 | 淡入 |
| 通知提示条 | med 180ms 缓出 | 淡入 + 上移，自动消失前可淡出 |
| 侧栏 / 抽屉 / 浮动目录 | panel 240ms | 宽度或位移，箭头方向 |
| 卡片列表出现 | 不动（直接出现） | 不做逐条入场 |
| 正文与 PDF 页面 | 不动 | 一律不加动画 |

- 跳到某条划线时，用该条自己的颜色闪一下，约 1 秒（记录色，不用品牌色）。
- 系统开启「减少动态效果」时，去掉位移，淡入 ≤ 120ms；骨架微光停止。
- PDF 阅读器必须同样处理 reduced-motion（当前缺失）。

### 3.9 无障碍

| 方面     | 要求                                                                    |
| -------- | ----------------------------------------------------------------------- |
| 对比度   | 正文、次要文字、链接、按钮文字 ≥ 4.5:1；四种方案 × 深浅色共八套全部通过 |
| 聚焦     | 每个可点元素有可见聚焦圈，用强调色 2px，偏移 2                          |
| 点击范围 | 桌面 ≥ 32×32，手机 ≥ 44×44                                              |
| 动效     | 尊重 `prefers-reduced-motion`                                           |
| 颜色之外 | 高亮不能只靠颜色区分，配合下划线、波浪线或左侧色条                      |
| 文字缩放 | 放大到 200% 时布局不破、内容不丢                                        |

**命中区的实现口径**：桌面所有可点元素的实际命中区 ≥ 32×32，用 padding 或透明的 `::before` 外扩，不用可见尺寸硬撑。卡片操作、删除、关闭、PDF 侧栏关闭、目录折叠箭头都必须外扩到 32。手机用 `--myz-hit-touch` 44。

**文字缩放的做法**：字号优先用九级 Token / rem，容器用 `max-width` 而不是 `width`，侧栏与弹窗在窄屏可折叠，避免 200% 下横向滚动。PDF 原页舞台允许横向滚动是唯一例外。

## 4. 组件

组件按"原子 → 布局/复杂 → 交互"排列：§4.1–4.16 是跨宿主的基础组件与规则；§4.17–4.22 是按场景补齐的设置、内容层、列表/侧栏、弹窗与 PDF 组件。密度由 `--myz-hit-*` 决定：紧凑 32 / 常规 36 / 触控 44。字号一律查 §3.5 的映射表，动效查 §3.8。

### 4.1 图标

- 来源：Lucide（MIT），只描边不填充，线宽 1.75，圆角端点。
- 尺寸：默认 16，36px 按钮里 20，手机 24。
- 点击范围：图标周围至少 32×32。

### 4.2 圆角

见 §3.7。所有取值从 `--myz-r-*` 取。

### 4.3 卡片

记录卡是一张纸片，不是仪表盘小部件。

| 属性       | 做法                                                           |
| ---------- | -------------------------------------------------------------- |
| 外观       | `--myz-surface` 底，1px `--myz-line` 边框，圆角 `--myz-r-lg`，内边距 12–16；**不加阴影** |
| 类型标签   | 标签 chip：高 22、界面字体 11/600、`--myz-tag-bg`/`--myz-tag-fg`；摘录用 `--myz-clip-bg`/`--myz-clip` |
| 引用与批注 | 长文字体 14–16，行高 1.55–1.6                                  |
| 来源行     | 界面字体 11，`--myz-muted`；来源截断最多约 120px，用 title 补全    |
| 正文限高   | `max-height: 20lh`，超出后卡片内部滚动                         |
| 页码徽标   | 高 20–22 的 pill，`--myz-warn-bg`/`--myz-warn`，文案「第 N 页」    |

**类型标签定稿**：标签只是标记，颜色由 §4.5 的 `--myz-tag-*` 决定，不再用 §旧文的 `--myz-accent-text`；摘录用 `--myz-clip-*`。卡片、Popup、PDF 标注行、查看器四处一致。

`20lh` 用行高作单位：换方案或调阅读字号时上限跟着字体缩放，不会出现小字卡片很高、大字卡片装不下的情况。

### 4.4 按钮

| 属性     | 做法                                              |
| -------- | ------------------------------------------------- |
| 高度     | 32 / 36 / 44，左右内边距 12                       |
| 文字     | 界面字体 13，字重 600                             |
| 圆角     | `--myz-r`（8），**不用胶囊**；胶囊只给采集条与分段控件 |
| 底色     | `--myz-control-bg`，边框 `--myz-control-border`           |
| 主按钮   | 实心 `--myz-accent`，文字 `--myz-on-accent`；一屏只有一个 |
| 危险操作 | 文字色 `--myz-error`，不用实心红                      |
| 聚焦     | 强调色 2px 外圈，偏移 2，必须 `:focus-visible`，不许去掉 |
| 禁用     | 整体透明度 45%，文字颜色不变；不用 40/60 等另一套值     |

**图标按钮**：正方形，命中区 ≥32；放在 36 的按钮行里时可见尺寸 32，图标 18。弹出菜单里的图标按钮跟随选项行高。

**例外**：分段控件（§4.19）与浮动工具条（§4.7/§4.18）用胶囊；分段控件的当前项用实心强调色，其余选中态见 §4.10。

### 4.6 输入框

| 属性 | 做法                                       |
| ---- | ------------------------------------------ |
| 高度 | 单行 36（紧凑 32），圆角 `--myz-r`             |
| 字体 | 搜索与设置用界面字体；批注用长文衬线       |
| 标签 | 界面字体 12，`--myz-muted`，距输入框 6；**不大写、不加字距** |
| 聚焦 | 边框变 `--myz-accent`，外加 3px 20% 强调色光圈 |
| 禁用 | `--myz-surface-2` 底，文字仍清晰               |

**原生控件的统一外形**（下拉、日期、文件，形状与输入框一致）

| 控件 | 做法 |
| ---- | ---- |
| `<select>` | 同输入框高度/圆角/边框/底色；右侧留出原生箭头空间，不自绘箭头；聚焦光圈同输入框 |
| `<input type="date">` | 外层用同输入框的容器包住，日历图标用 Lucide `Calendar` 放在行尾触发 `showPicker()`；隐藏 WebKit 默认日历图标 |

| 紧凑场景 | PDF 侧栏搜索框高 32，圆角 `--myz-r`，聚焦光圈同规则 |

### 4.7 采集条

选中文字后浮出的工具条，是采集唯一的入口。

| 属性        | 做法                                            |
| ----------- | ----------------------------------------------- |
| 形态        | 胶囊，图标 32，间距 4，跟随选区，层级最高       |
| 底色        | 固定 `--myz-overlay`（`#141413`），不跟方案与深浅色 |
| 文字 / 图标 | `--myz-overlay-text`                                |
| 边界        | 深色投影 + 1px 浅色描边（见下）                 |
| 高度        | 紧凑                                            |
| 动作        | 划线、摘录、截取、搜索；阅读器内另有「翻译」     |
| 子按钮      | 32×32，圆角 `--myz-r-pill`（固定深色工具条的例外），图标 16 |
| 悬停 / 聚焦 | 悬停 `--myz-overlay-hover`；聚焦 `--myz-overlay-text` 2px 外圈 |
| 动效        | 只做底色淡入（fast）；**不做 `scale` 缩放**，§2.8 只解释变化 |

**为什么固定深色**：它出现在任何网页上，无法知道自己压在什么背景上。固定深色在哪都稳定。深色页面上靠一圈约 16% 白的 1px 描边勾出轮廓，浅色页面上靠普通深色投影浮起——两样同时写在 `box-shadow` 里，互补：

```css
box-shadow:
  0 8px 24px rgba(0, 0, 0, 0.35),
  0 0 0 1px rgba(255, 255, 255, 0.16);
```

**阅读器与网页内的翻译**：PDF / EPUB 采集条和网页采集条都在划线、摘录之外多一个「翻译」（§4.24），放在截取与搜索之间。跨域宿主页的 `Permissions-Policy` 可能禁用端上模型，此时按不支持给出明确文案，不报错。

**Rationale** 采集条是临时的操作层，不是用户的阅读环境；固定深色让它在任何页面上都保持同一个熟悉的样子，也与 §2.3 一致。

### 4.8 弹窗和浮层

| 属性     | 做法                                                            |
| -------- | --------------------------------------------------------------- |
| 采集编辑弹窗 | 宽 **320**，`--myz-surface` 底，圆角 `--myz-r-lg`，带阴影；装样式 / 标签 / 调色盘 |
| 批注浮层 | 宽 **280**（网页与 PDF 一致；内容与行为见 §4.18）               |
| PDF 批注栏 | 浮动 **280**（与网页一致）                                       |
| 长文阅读 | 走查看器页面，不用大模态                                        |
| 遮罩     | 只有居中、会丢数据的确认类对话框才加不透明遮罩；采集小卡片不加 |
| 透明层   | **允许**用一个透明的全屏层来居中、承接"点外侧关闭"；它本身不画底色、不模糊背景 |
| 关闭     | Esc 关闭；点外侧只关不会丢数据的；关闭按钮用 Lucide `X`，不用 `×` 字符 |
| 聚焦     | 打开时落到第一个输入框，关闭后回到触发按钮；对话框边界加 `role="dialog"` `aria-modal` |
| 扩展弹窗 | 360 宽，属于系统面板，不是对话框组件（见 §4.21）                 |

**宽度定稿**：批注浮层（只读/就地编辑）统一 **280**；采集编辑弹窗（有样式、标签、调色盘）用 **320**；不再出现 240 / 300 / 其他值。

**`RecordModal` 并入查看器**：记录的长文阅读与编辑一律走查看器页面，不再保留大对话框。查看器承担原文还原、下一条/上一条、编辑批注与标签；不再出现 `max-w-5xl` 全屏遮罩式弹窗。关闭图标若仍需在别处出现，用 Lucide `X`，不用 `×` 字符。

### 4.9 卡片瀑布流

文库的记录列表。

| 属性     | 做法                                                  |
| -------- | ----------------------------------------------------- |
| 列数     | 窄屏 1，中等 2，宽屏 3                                |
| 间距     | 列间距与行间距都用 12                                 |
| 卡片高度 | 跟内容走，不裁成等高；正文限高 `20lh`，超出后内部滚动 |
| 排序     | 按"时间"或"文中顺序"                                  |

**Rationale** 记录长短差别大，等高网格会给短记录留大块空白。

### 4.10 菜单和目录的层级

| 问题     | 做法                                                       |
| -------- | ---------------------------------------------------------- |
| 从属关系 | 子项缩进 12–16，字号小一档或颜色更淡，不画引导线           |
| 分组     | 组标题用 10 号大写字加 `--myz-muted`；组之间一条细线，不用空行 |
| 层叠深度 | 最多两层（组 → 项）。需要第三层时改为跳到单独面板          |
| 重点     | 当前项用"浅底 + 强调色文字"，不用实心填充；次要信息靠右    |
| 可折叠   | 折叠箭头放最左，点标题整行展开；展开状态记在本地                |
| 长目录   | 与正文滚动联动、当前节高亮；不自动滚动抢位置                    |

**选中态统一口径**

- **列表项、导航项、目录项、侧栏项、设置导航项**：当前项用「`--myz-surface-2` 浅底 + `--myz-accent-text` 文字 + 600 字重」，不用实心强调色填充。
- **分段控件与分页**：当前项属于紧凑控件而非列表项，用实心 `--myz-accent` + `--myz-on-accent`（见 §4.19）。
- 不允许出现第三种：半透明强调底 + 强调色边框的写法只在弹出/选中卡片（如配色方案选择、PDF 标注项）使用，且必须同时有强调色文字。

**分支图标**：目录/菜单里表示展开折叠的箭头用 Lucide `ChevronDown`/`ChevronRight`，图标按钮命中区 ≥32。

| ---------- | ----------------------------------------------------------- |

### 4.15 空、加载、出错

**状态必须按它实际出现的位置呈现**，不是一律塞一个灰框：可以是整页、整面板、卡片内、列表内一行。

| 情况        | 做法                                                    |
| ----------- | ------------------------------------------------------- |
| 空          | 一个图标（Lucide，22–24）+ 一句状态 + 一句下一步，不写"无数据" |
| 加载        | 与内容同高的骨架条，颜色走 `--myz-skeleton`；可加很淡的微光（reduced-motion 时停） |
| 出错        | 错误色图标 + 说明可能原因 + 一个重试或替代动作（按钮）  |
| 成功 / 提示 | 提示条贴近操作位置，几秒后自动消失                      |

**状态组件的形态**

| 属性 | 做法 |
| ---- | ---- |
| 骨架条 | 圆角 `--myz-r-sm`；高度按行高取（正文行 12–14）；一组 2–3 条，宽度错落（70% / 45%） |
| 空状态图标 | `--myz-muted`；出错图标用 `--myz-error`；尺寸 22–24 |
| 文案 | 一句状态（正文级）+ 一句下一步（说明文字级），都不加句号客套 |
| 错误重试 | 次要按钮（§4.4），紧贴错误文字下方，不要跳走 |
| 提示条 | 底色固定 `--myz-overlay`、文字 `--myz-overlay-text`，圆角 `--myz-r`，内边距 12/14，最大宽 280 |
| 提示条位置 | 贴近触发的操作（采集/看板在右上、设置内联在操作行尾）；同一时刻同一件事只出现一处 |
| 提示条时长 | 3–4 秒后消失；可堆叠但最多 3 条，新的在下方，旧的先消失 |
| 提示条动作 | 默认不带按钮；确需"撤销"时给一个文字动作，且点击后立即消失 |

设置页的行内反馈用 `.status-line`（主题文本色：`--myz-muted`/`--myz-error`/`--myz-success`），不用固定深色 toast；跨页面、会浮起的通知才用 `--myz-overlay`。

### 4.16 专注阅读和重排

（在展示页里与"阅读字号五档"一起放在"字体与排版"一节。）用于我们自己保存的文字与 HTML 文章，不适用于 PDF 原页和网页上的划线。

| 属性   | 做法                             |
| ------ | -------------------------------- |
| 字体   | `--myz-read`                         |
| 字号   | `--myz-read-size-1…5`，默认第三档 18 |
| 行距   | `--myz-read-leading`，默认 1.8       |
| 字间距 | `--myz-read-tracking`，默认 0.01em   |
| 栏宽   | `--myz-read-measure`，默认 38em      |
| 页边距 | `--myz-read-gutter`，默认 24         |
| 纸色   | **跟随配色方案与深浅色**（不写死浅色） |
| 外框   | 只留退出与排版控件               |

**本期不做字号切换控件**：专注阅读后续会整体重做，所以这版只保证纸色跟随方案与深浅色、排版按五档默认值渲染；字号/行距/栏宽的调节控件留到重做时一起做。

**Rationale** 字号、行距、字间距、栏宽、页边距全部变量化，用户能调，未来 EPUB 直接复用同一套。PDF 走"原页 + 缩放 + 坐标标注"，与这套无关。

### 4.17 设置

设置是正式场景（见 §6），不再是"规范没写到的空白"。布局是「侧栏 240 + 内容」两栏，窄于 900 收成抽屉。

| 组成 | 做法 |
| ---- | ---- |
| 页面标题 | 区块标题级 24/600，下面一句说明 13 `--myz-muted`；右上角"返回文库"用链接按钮 |
| 分组卡 | `--myz-surface` 底、1px `--myz-line`、圆角 `--myz-r-lg`、内边距 20、组间距 16；**不加阴影** |
| 分组头 | 小节标题级 17/600 + 说明 12 `--myz-muted`；右侧放分组级动作（如"恢复默认"） |
| 侧栏分组标题 | 标签级 10–11/600 大写 + `--myz-muted`；组间距 16，项间距 4 |
| 侧栏项 | 常规密度 36；当前项按 §4.10 列表项规则（`--myz-surface-2` 浅底 + `--myz-accent-text`） |
| 字段 | 默认「左标签 + 右控件」单行；复杂控件纵向。详见 §4.23 |
| 开关 | 见下 |
| 下拉 / 日期 / 文件 | 复用 §4.6 的控件外形与 §4.23 的输入组规则 |
| 保存 | 主按钮（一屏一个）+ 行内状态：未保存 `--myz-warn`、已保存 `--myz-success`、进行中 `--myz-muted`；不用 toast |

**开关 ToggleSwitch**

| 属性 | 做法 |
| ---- | ---- |
| 轨道 | 44×24，圆角 `--myz-r-pill` |
| 圆点 | 直径 16，距边 4；关时靠左，开时靠右，120ms 位移 |
| 关态 | `--myz-surface-2` 底 + `--myz-line` 边框 |
| 开态 | `--myz-accent` 实心，圆点 `--myz-on-accent` |
| 聚焦 | 强调色 2px 外圈，偏移 2；底层用 `sr-only` checkbox 保留语义 |
| 禁用 | 整体 45% |

**密钥 / 键值 / 状态行**：用「label（12 muted）+ 值（紧凑正文）+ 状态 pill」。状态 pill 高 22、11/600、实色 `*-bg`/`*`（成功/错误/提示三色见 §3.3）；键值行间距 8。

**导入表单**：文件框 + 来源下拉 + 冲突策略下拉 + 行内状态行，全部走 §4.6；状态行在动作按钮右侧。

**外观：配色方案选择卡**：4 张等宽小卡，`role="radiogroup"`。卡内是"页面底 + 卡片 + 强调色点"的缩略预览；当前项 `--myz-accent` 边框 + 2px `accent/20` 外圈；卡下标签用说明文字级。主题（亮/暗/跟随系统）控件在顶栏和设置页**共用同一个 `ThemeToggle`**，不再各写一套下拉。

### 4.18 内容层批注组件

内容层三件套：采集条（§4.7）、紧凑高亮条、完整批注浮层。前两者固定深色，完整浮层跟随主题。

**完整批注浮层（Inspector）**

| 属性 | 做法 |
| ---- | ---- |
| 形态 | 浮动面板，宽 **280**，`--myz-surface` 底、圆角 `--myz-r-lg`、`--myz-shadow`；跟随方案与深浅色 |
| 位置 | 网页里锚定选中文字右上方；空间不足翻到下方；右侧固定时垂直居中 |
| 内容 | 引用（长文衬线 14、左侧 `--myz-highlight-color` 3px 条）+ 批注输入 + 标签 + 颜色/样式 |

**顶栏**

| 属性 | 做法 |
| ---- | ---- |
| 高 | **44（含 1px 底边）**，吸顶铺满 |
| 底 | `--myz-well-chrome` + `--myz-well-border` 底边，可加轻微 backdrop blur |
| 按钮 | 命中区 32，圆角 `--myz-r`，`--myz-well-control-bg`/`--myz-well-control-border`，图标 16 Lucide |
| 页码 | `--myz-mono` + `tabular-nums`，`--myz-well-muted`；无页时占位 `—` |

**标注面板**

| 组成 | 做法 |
| ---- | ---- |
| 筛选 chip | 文案用「摘录」（不是「文字」）；可见高 22–24、命中区 ≥32、圆角 pill；当前项 `--myz-accent-text` + 强调色边 |
| 搜索框 | 紧凑 32、圆角 `--myz-r`、聚焦 3px 20% 光圈 |
| 分组标题 | 「第 N 页」用标签级 + `--myz-well-muted`（不做大写） |
| 行 | 底走 `--myz-well-control-bg`（不是 `--myz-surface-2`）；4px 色条 + 文字（长文衬线 14，两行截断）+ 批注 13 + 标签；当前项浅底 + `--myz-accent-text` |
| 标签 | 窄侧栏例外：高 20（§4.5 的 22 之外唯一允许值） |
| 空态 | 「这里还没有记录」+ 一句下一步 + 图标 |

**Inspector / 保存**：浮动的批注面板同 §4.8（280）；保存/删除按钮按 §4.4（13/600、高 32、删除只用文字 `--myz-error`，不用实心红）；批注输入 14–15；标签用共享 `TagInput`（回车生成，不解析逗号）；调色盘用用户调色盘 + §4.14 可读色名。

**原页与划线**

| 属性 | 做法 |
| ---- | ---- |
| 原页 | 始终保持白色原件；抬升投影用 `--myz-shadow`，不写死固定值；原页不做圆角 |
| 涂色 | 图层透明度：默认 35%，选中 55%（§3.4） |

### 4.23 表单与字段

§4.6 定义单个输入框，§4.17 定义设置分组；这一节定义表单本身的布局、状态、校验与输入组。

**布局**

| 场景 | 做法 |
| ---- | ---- |
| 单行（默认） | 左 label、右控件，`justify-between`；控件宽 288，简单项一行一个，最省纵向空间 |
| 纵向 | 控件需要整行时用：文本域、标签输入、调色盘、方案卡、文件选择、长文本 |
| 分组 | `--myz-surface` 卡片 + 1px `--myz-line` + 圆角 `--myz-r-lg` + 内边距 20；组内行距 16；组标题 17/600 |
| 多列 | 表单列最窄 280；容器窄于「2×列 + 间距」时降为单列；同一行不超过两列 |
| 窄屏 | 容器窄于 640 时，单行布局降为纵向（label 在上） |
| 日期区间 | 两列 + 中间连接符，不拆成两行 |

**标签与帮助**

- label 用界面字体 13（`--text-label`）或 12，**正文色**（不是 `--myz-muted`，保证可读）；距控件 6。
- 可选字段标「可选」；不要给必填字段加星号再配复杂说明。
- 帮助文本用说明文字级 `--myz-muted`，放在控件下方；错误文本替换帮助文本的位置，不叠加。
- label 必须关联控件（`<label for>` 或包裹）；一组相关控件用 `<fieldset>` + `<legend>`。
- 不用 placeholder 当唯一标签。

**字段状态**

| 状态 | 做法 |
| ---- | ---- |
| 默认 | `--myz-control-bg` 底 + `--myz-control-border` 边 |
| 悬停 | 边框转强调色边（可选） |
| 聚焦 | 边框 `--myz-accent` + 3px 20% 强调色光圈（§4.6） |
| 已填写 | 值用 `--myz-text` |
| 禁用 | 整体 45%，不响应交互 |
| 只读 | `--myz-surface-2` 底、文字仍清晰、可选中 |
| 错误 | 边框 `--myz-error`，下方错误文字 12、`--myz-error` |
| 成功 | 用行内状态文字（§4.15），**不给字段加绿框**，避免与错误并存时歧义 |

**校验与反馈**

- 就地提示在字段下方，不用 toast；提交失败时聚焦第一个错误字段。
- 错误文案说清怎么改，不写「非法输入」。错误源和控件用 `aria-invalid` + `aria-describedby` 关联。
- 提交中：主按钮禁用 + 「保存中…」；成功后行内状态文字说「已保存」（§4.17），不用固定深色提示条。
- 破坏性动作（删除、重置）放次位；删除用文字 `--myz-error`，不实心红。

**输入组**

- 日期：外层同输入框容器，行尾 Lucide `Calendar` 触发 `showPicker()`，隐藏 WebKit 默认图标。
- 文件：隐藏原生 input（`sr-only`），用一个 control 按钮 + 文件名（截断、`--myz-caption`）组成整组，整组可点。
- 前缀 / 单位：前缀用 `--myz-muted` 文本置于控件左侧，不单独做标签。
- 搜索：单行、圆角 `--myz-r`、聚焦 3px 20% 光圈；尺寸走 `--myz-hit-*`。

**无障碍**

- 每个控件有可读 label；必填 `aria-required`；错误 `aria-invalid` + `aria-describedby`。
- 支持浏览器自动填充而不破版；`autocomplete` 语义正确（如 `email`、`current-password`）。

**Rationale** 表单是最容易出现"每个页面一套"的地方：标签时而上时而下、错误提示时而 toast 时而红框、下拉时而原生时而定制。把布局与状态收敛成一条规则（简单项左右、复杂项纵向、错误就地、提交用行内状态），新加一个设置项就是套模板，不用再讨论。

### 4.24 翻译浮层

选中文字后点采集条上的「翻译」，在选区附近浮出的只读结果面板。端上模型完成翻译，内容不出设备；译文可复制。段落结构**取自文档本身**（HTML/EPUB 按块级元素切分，PDF 按几何分行分段），不是靠换行猜测，逐段翻译后再拼回，所以原文与译文都保持段落结构。PDF、EPUB 与网页采集条共用同一个组件（样式在共享 `translation-popover.css`）。

| 属性 | 做法 |
| ---- | ---- |
| 形态 | 宽 `min(400px, 100vw - 32px)`，`--myz-well-chrome` 底、1px `--myz-well-border`、圆角 `--myz-r-lg`、`--myz-shadow`；`role="dialog"` |
| 定位 | 锚在选区下方居中（`translateX(-50%)`）；下方空间不足时翻到选区上方；上下左右都限制在视口内，整体最高 `min(60vh, 560px)`，长文在面板内滚动，不遮住整页 |
| 拖动 | 按住头部可拖动（头部 `cursor: grab`，拖动中 `grabbing`）；拖动后仍限制在视口内 |
| 内容 | 头（`Languages` 图标 + 「翻译」+ 语言对 + 关闭 `X`）、原文引用、状态、译文、动作 |
| 原文引用 | 左侧 3px 强调色，`--myz-surface-2` 底，长文衬线 14，保留换行（`pre-wrap`）；最高 **5 行**，超出在框内滚动，避免原文挤占译文 |
| 语言对 | 「检测到的源语言 → 目标语言」，界面字体 12，`--myz-well-muted`；检测中显示「检测中」 |
| 译文 | 长文衬线 14、行高 1.7、`pre-wrap`，与原文同一滚动区；按段翻译并保留段落结构（段间空行） |
| 状态 | 识别中 / 下载语言包（带 0–100% 进度条 `--myz-accent`）/ 翻译中；无静默失败 |
| 出错 | 文案 `--myz-error`，给出「重试」；源=目标、暂不支持、超配额、不支持浏览器各有明确文案 |
| 动作 | 「复制」（主按钮，成功后短暂变「已复制」）；出错时「重试」；进行中可「取消」 |
| 动效 | 淡入 med 180ms 缓出（§3.8）；进度条宽度 fast；拖动时不动画；尊重 reduced-motion |
| 无障碍 | 打开聚焦浮层；Esc、点外侧、关闭按钮都关闭；关闭后回到触发按钮；进度用 `role="progressbar"` |
| 缓存 | 译文按 `源:目标:文本哈希` 存本机：阅读器用 `myz_translate_db`，网页内容层用扩展 `chrome.storage.local`（content script 的 IndexedDB 属于宿主页 origin，不能用）；都不同步、不出设备 |

**Rationale** 翻译是阅读中的一个临时动作，和批注一样「看一眼就走」，所以沿用浮层而不是页面或大模态；只读、不写回记录，因此没有编辑区。端上模型需要下载语言包，进度、取消与出错必须当场说清楚，否则用户会以为按钮坏了。

### 4.25 Inbox 队列组件

Inbox 是新采集内容的处理队列，不是文库副本，也不是按时间、主题或页面重排的发现页。它消费同一组 `MyZRecord`，但额外显示用户工作流状态。保留、归档、删除和编辑的权威结果必须能回到文库。

**页面骨架**

| 组成 | 做法 |
| ---- | ---- |
| 导航 | 顶层独立项「Inbox」；文库仍叫「文库」；Inbox 应用实现尚未落地 |
| 左侧栏 | 桌面 240：队列状态导航（待处理/稍后处理/已标记）+ 标签列表；标签为拖拽投放目标（拖记录上去即打标签），点击标签筛选队列；窄屏收进抽屉 |
| 页面头 | 标题 Inbox（区块标题级 24/600）+ 「待处理 N 条 · 最早积压 X」的说明；右侧提供「直接入文库」语义说明或返回文库 |
| 状态筛选 | 在左侧栏：待处理（默认）/ 稍后处理 / 已标记；不使用“时间 / 主题 / 页面”作为主导航 |
| 搜索 | 高 36、圆角 `--myz-r`，搜索正文、批注、标题、标签和来源 |
| 批量工具 | 选择框 + 批量保留、归档、稍后、删除；动作栏与选择数量绑定，未选中时不抢视觉焦点 |
| 内容 | 单栏队列；卡片、列表行和详情面板走 `--myz-surface`、`--myz-line`、`--myz-r-lg`，无阴影 |
| 窄屏 | 左栏收进抽屉；行内动作收进底部操作区；详情从底部抽屉打开；不产生横向滚动 |

**InboxRecordRow**

| 属性 | 做法 |
| ---- | ---- |
| 命中区 | 行最小高 56、左右 12；选择框和动作按钮各自 ≥32×32，不能用整行 button 包含多个按钮 |
| 内容顺序 | 选择框 + 类型 chip + 状态 pill + 摘录/批注片段（最多 2–4 行）+ 来源标题/域名 + 时间 |
| 元信息 | 页码、章节、语言、内容长度和 enrichments 状态用说明文字级 12–13 `--myz-muted` |
| 正文 | 原始片段用 `--myz-read`、14/400/1.55，文字 `--myz-text`；自动信息不使用阅读正文级字号 |
| 状态 | `pending` 用提示色，`snoozed` 用中性色，`marked` 使用标记图标与文字，不仅依赖颜色 |
| 动作 | 行内提供标记、保留、稍后、归档、删除；删除用危险文字按钮，不使用实心红色 |
| 数据边界 | 摘录、标题、来源来自原始记录；关键词、代表句和重复候选明确标为自动信息，不写回用户标签 |

**InboxEnrichmentPanel**

| 属性 | 做法 |
| ---- | ---- |
| 关键词 | 2–5 个 chip，复用 §4.5 尺寸但不等同于用户标签；点击可查看命中原句 |
| 代表句 | 直接引用原文 1–3 句，左侧使用 `--myz-info` 3px 条；显示来源，不叫“AI 摘要” |
| 重复提醒 | 使用「可能重复」/「已有相似记录」提示；展示候选记录和相似原因，不自动合并或删除 |
| 来源上下文 | 同 URL、同 PDF 页、同 EPUB 章节的记录数量与入口；不替代文库来源侧栏 |
| 计算状态 | 处理中、已完成、已跳过、失败都就地显示；失败不阻塞队列动作 |
| 隐私 | enrichments 在本地可重建，不默认同步；设备间可能暂时不同，文案必须说明“本机分析” |

**InboxStatusPill**

| 状态 | 文案 / 视觉 |
| ---- | ---------- |
| `pending` | 「待处理」，使用 `--myz-info-bg` / `--myz-info` |
| `snoozed` | 「稍后处理」，使用 `--myz-surface-2` / `--myz-muted`，显示到期时间 |
| `kept` | 「已保留」，只在处理反馈或文库筛选中显示，不留在默认队列 |
| `archived` | 「已归档」，使用中性色；归档仍可在文库筛选、搜索和导出中找到 |
| `marked` | 「已标记」或标记图标；它是独立标记，不改变状态 |

**详情抽屉**

- 宽度桌面 320–360，窄屏底部抽屉，沿用 §4.8 的浮层、焦点和 Esc 规则。
- 先显示原始摘录、来源和动作，再显示自动 enrichments；自动信息不能盖过用户内容。
- 编辑正文、批注和标签跳转到现有查看器，不在 Inbox 复制编辑器。
- 保留入文库后回到文库记录；归档后显示“可在文库的归档筛选中找到”。

**Rationale** Inbox 的价值是把“刚采集”和“确认保留”分开，并让用户能快速完成决定。自动信息只能减少判断成本，不能增加一个不可解释的自动分类系统。队列动作必须先于 enrichments 可用，模型或本地索引失败不能把用户锁在 Inbox 里。

## 5. 内容与文案

**基调**：短、能做、说人话。空状态是说明，不是报错。

| 说的是什么       | 就这样写       | 不要写               | 原因                     |
| ---------------- | -------------- | -------------------- | ------------------------ |
| 产品名           | MyZ            | 通用智能助理         | MyZ 聚焦采集与回看；Inbox 的本地线索不是聊天助手 |
| 给选区上色       | 划线           | 高亮、划线标注       | "高亮"是样式名，容易混   |
| 只保存文字       | 摘录           | 保存文字、文字       | 与划线并列的一种记录     |
| 自己写的那句     | 批注           | 笔记、评论           | "评论"听着像社交软件     |
| 同一个网页的汇总 | 来源           | 网页书签             | 网页和 PDF 都用这个词    |
| 回到原本的位置   | 打开原文       | 定位、查看           | 用户知道点下去会发生什么 |
| 按文中位置排序   | 文中顺序       | Range                | 是代码里的字段名         |
| 只看网页正文     | 专注阅读       | 禅定模式             | "禅定"只留给代码         |
| 一条都没找到     | 这里还没有记录 | 没有符合条件的记录。 | 说清楚情况，不写客套话   |
| 记录类型筛选     | 摘录           | 文字                 | 与"只保存文字"同一个词   |
| 列表里没有批注   | 还没有批注     | 无批注、暂无批注     | 空状态是说明，不是标签   |
| 列表里没有标签   | 还没有标签     | 无标签               | 同上                     |
| 记录正文为空     | 这里还没有内容 | 无可展示内容         | 说清楚现状               |
| 同步协议版本     | 同步版本       | Manifest 版本        | 不暴露内部字段名         |
| 打开 PDF         | 在阅读器中打开 | 定位、查看           | 与"打开原文"区分动作     |
| 新内容处理入口   | Inbox          | 待办箱、知识中枢     | Inbox 是采集处理队列，不是第二文库 |
| 保留内容         | 保留入文库     | 完成、保存一下       | 明确表示记录进入文库常规视图 |
| 隐藏但不删除     | 归档           | 丢弃、删除           | 记录仍可在文库归档筛选、搜索和导出中找到 |
| 自动关键词       | 关键词         | 标签、主题           | 关键词是本地线索，不写入用户标签 |
| 自动原文摘取     | 代表句         | AI 摘要、结论        | 代表句直接来自原文，不改写事实 |

## 6. 场景

同一套外框在不同场景下的样子。实现时共用组件，只改密度与内容。

| 场景         | 说明                                                              |
| ------------ | ----------------------------------------------------------------- |
| 文库         | 顶栏（标题 + 分段 + 搜索 + 主题）、来源侧栏 240–280、记录卡瀑布流 / 列表 |
| Inbox        | 采集处理队列；待处理 / 稍后处理 / 已标记；保留、归档、删除；关键词、代表句、重复提醒和来源上下文 |
| 设置         | 侧栏 240（分组导航）+ 分组卡；字段、开关、下拉、配色方案选择卡     |
| 扩展弹窗     | 360 宽，系统面板，记录行带 3px 颜色条                             |
| 网页采集     | 采集条浮在原文上（划线/摘录/截取/翻译/搜索）；完整批注浮层 280（可就地编辑） |
| 查看器       | 长文阅读与记录编辑走独立页面，不用大模态；记录按文中顺序还原、可跳上/下一条 |
| PDF 原页     | 顶栏 44（翻页、页码、缩放、打开）、目录/标注停靠侧栏 240、原页舞台、批注 Inspector 浮动 280、选中可端上翻译 |
| 专注阅读     | 单栏长文，只留退出与排版控件                                      |
| EPUB         | 本地文件；重排正文 + 目录侧栏 + 高亮/摘录 + 选中翻译，复用阅读设置与记录模型 |

**PDF 顶栏**：吸顶铺满，跟随方案与深浅色，高度 44（含边框），使用 `--myz-well-*` 一组 Token。
