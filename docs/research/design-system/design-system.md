## 0. 怎么用这份文档

1. **Token 优先**。颜色、字体、圆角、尺寸、动效时长都定义在 §3.2。实现时不要写死具体值，引用变量名。
2. **配色方案与深浅色正交**。方案决定"外框气质"，深浅色决定明暗。二者组合出的变量值见 §3.2 的四张表。
3. **原文不属于我们**。网页和 PDF 的排版由对方决定，我们只叠加痕迹；可改的只有产品自己的外框。见 §2 原则一、二。
4. **改动流程**：先改本文件，再改实现。

## 1. 产品与使用场景

MyZ Annotator 是一个本地优先的标注与阅读工具：用户在网页和 PDF 上划线、摘录、写批注，之后回到文库里重新翻看。Inbox 是新采集内容的处理队列；基础采集、队列动作和文库不依赖 AI。关键词、代表句、重复提醒和来源上下文是可解释的本地辅助信息，端侧语义模型属于后续实验。

**目标用户**：个人知识工作者与学习者本人。一边读一边记，几个月后还要翻出来用。

**两条主线动作**：

| 动作                         | 频率       | 对设计的要求                                 |
| ---------------------------- | ---------- | -------------------------------------------- |
| 采集（划线、摘录、截取）     | 一天很多次 | 快，出现在视线附近，不打断阅读，不遮挡上下文 |
| 回看（文库、Inbox、查看器、阅读器） | 一天几次   | 找得到；未处理内容可集中处理，已保留内容可长期回看 |

**由此推导的使用习惯**：

| 习惯                 | 对设计的要求                               |
| -------------------- | ------------------------------------------ |
| 选中一段马上就想划线 | 采集条在视线附近出现，一步到位             |
| 常在深夜或通勤路上读 | 深色和浅色都要完整可用                     |
| 一读就是半小时以上   | 长文用衬线体、纸色底、宽行距，界面退到后面 |
| PDF 占很大比例       | 原页不动，页码和图注要对得上               |
| 几个月后回来找一句话 | 记录能按来源与文中顺序还原                 |
| 既在电脑也在手机上   | 跨设备共用同一套视觉语言                   |

## 2. 设计原则

八条。每条后面是理由，用来判断新方案是否成立。

### 2.1 原页不重排

网页用网站自己的排版。PDF 用 pdf.js 画出的原页，划线是叠在页面坐标上的一个框。缩放只改整页大小，不改断行。

**Rationale** 产品承诺是"点开原文，还能看见那句话就在原处"。一旦重排，页码、分栏、图注、标注坐标全部失效。EPUB 可以重排，是因为它本身没有固定页，与 PDF 是两回事。

### 2.2 只统一属于我们的部分

采集条、弹窗、文库、PDF 阅读器的外框共用同一套 Token 与组件，深浅色跟随用户设置。原文本身不换字体。

**Rationale** 外框是我们的产品，原文是别人的。只统一能统一的，扩展、桌面、手机才能共用同一份代码。

### 2.3 划线是记录，不是装饰

五个高亮颜色是用户自己定的记录数据，换配色方案和深浅色都不改。品牌色只用于按钮、当前项和链接，不与划线抢颜色。

**Rationale** 用户可能已经用某个颜色标了很久，换主题改写颜色等于打乱他整理过的东西。采集条是临时的操作层，不跟随主题。

### 2.4 按阅读时长选字体

界面用系统无衬线字体。需要长时间阅读的内容用衬线体：西文 Newsreader，中文按界面语言选对应的 Noto Serif 地区版本。

**Rationale** 按钮看一眼就走，摘录会盯着读很久。西文和中文同一类气质，长文里插入英文不突兀；界面跟系统走，插件才不像贴上去的一层皮。

### 2.5 松紧由行高定，不是由面板定

工作区（文库、Inbox、素材、设置）按**行密度**选档，控件高度跟着行高走；同一种组件只改高度，不改长相。

| 档 | 列表行高 | 控件高 | 用在哪 |
| -- | -------- | ------ | ------ |
| 紧凑 | 40（`--myz-row-h-dense`） | 28（`--myz-hit-dense`） | 素材网格标题行、表格、工具条、行尾图标；只看不读的场合 |
| 标准 | 56（`--myz-row-h`） | 32（`--myz-hit-compact`） | 文库、Inbox、设置列表——**默认档** |
| 表单 | — | 36（`--myz-hit-regular`） | 输入框、下拉、主操作按钮 |
| 触控 | 64 | 44（`--myz-hit-touch`） | 窄屏（< 640）与所有触屏命中区 |

**Rationale** 旧规则是「采集条 32、文库 36、手机 44」——它按「这是哪个面」定松紧，没管行距。结果行压到 56 了按钮还是 32，行高永远下不去；反过来说，一个面里按钮 36 却要求行 40，两者互相顶。改成按行高定档之后，「这一行多高」是唯一变量，控件高度是它的函数，不再需要每个面单独判断。

采集条与浮层仍用 32 / 胶囊（§4.7、§4.18），因为它们是浮在别人的文字上，不属于工作区行密度体系。

**导航项与侧栏项统一 32，不进 40 也不进 28**：它们是「点一下就走」的一级导航，不是被阅读的列表行；28 太窄（左右各 8 只剩 12 给图标 16），40 又会让一个 6 项的导航占掉 240 的高度。

### 2.6 默认不用阴影

层级用留白和一条细线建立。阴影只给真正浮起来的层：采集条、批注面板、弹窗、下拉、目录浮层。

**Rationale** 到处加阴影和大圆角会与网页本身抢层级，也让文库看着像数据管理工具。

### 2.7 一个动作一个词

同一个功能只用一个说法。代码里的内部叫法可以保留，但不能印在按钮上。

**Rationale** 用词不稳定，按钮、提示、空状态就无法复用。词表见 §5。

### 2.8 动效只解释变化

动效回答"它出现了""找到了"。正在读的文字保持在原位。

**Rationale** 划线和阅读都要求注意力集中，正文一动会被误认为页面在跳。切换深浅色只改颜色。

## 3. 基础

### 3.1 配色方案

默认 **米纸（paper）**，另提供 **冷灰（slate）**、**青瓷（celadon）**、**赭石（ochre）**，由用户在设置里选择。方案只改变产品外框，不改划线五色、语义色和组件尺寸。

| 方案                 | 定位                              | 亮底色    | 暗底色    |
| -------------------- | --------------------------------- | --------- | --------- |
| `paper` 米纸（默认） | 暖米 + 油墨蓝，长时间阅读不刺眼   | `#F5F4ED` | `#141413` |
| `slate` 冷灰         | 中性冷灰 + 靛蓝，接近系统默认观感 | `#F8FAFC` | `#0F172A` |
| `celadon` 青瓷       | 极浅青绿 + 深绿                   | `#F2F4EE` | `#101512` |
| `ochre` 赭石         | 暖沙 + 铁锈红，更旧的纸感         | `#F6F0E6` | `#17130F` |

实现方式：根元素上两个属性，`data-scheme="paper|slate|celadon|ochre"` 与 `data-theme="light|dark"`。

**规则**

- 语义色（警告、错误、成功、提示）只跟深浅色，不跟方案。
- 高亮五色属于记录数据，与方案、深浅色都无关。
- PDF 阅读器外框跟随方案与深浅色；PDF 页面本身永远是原件颜色。
- **固定深色的范围就三样**：网页采集条、点击已有划线弹出的紧凑三按钮高亮条、通知提示条（`--myz-overlay`）。完整批注浮层、PDF 阅读器 Inspector、设置页提示都跟随主题。固定深色组件内部统一用 `--myz-overlay-text` 做文字与聚焦色，`--myz-overlay-hover` 做悬停底（见 §4.7、§4.18）。
- 设置页里的行内状态文字（`.status-line`）跟随主题，不用固定深色；只有会浮起、可能压在任意内容上的通知才用 `--myz-overlay`。

### 3.4 划线颜色

五色属于记录数据，存在记录里，换方案与深浅色都不改。

| Token      | 值        | 名称         |
| ---------- | --------- | ------------ |
| `--myz-mark-1` | `#b58900` | 琥珀（默认） |
| `--myz-mark-2` | `#ef476f` | 珊瑚         |
| `--myz-mark-3` | `#9f7aea` | 紫           |
| `--myz-mark-4` | `#38bdf8` | 天蓝         |
| `--myz-mark-5` | `#34d399` | 青绿         |
| `--myz-highlight-color` | 逐条内联，默认 `var(--myz-mark-1)` | 当前这条记录的颜色通道 |

**`--myz-highlight-color`** 不是主题色，而是"当前这条记录自己的颜色"：渲染一条划线/标注时把它内联到该元素上，规则里统一引用它。这样同一份规则能同时服务五色，且颜色永远来自记录数据而不是主题。

**三种样式怎么画**

| 样式             | 画法                                                                                 |
| ---------------- | ------------------------------------------------------------------------------------ |
| 涂色 paint       | `background: color-mix(in srgb, <色> 42%, transparent)`；圆角 3px，左右各 2px 内边距 |
| 下划线 underline | 不填底；线用实色，粗 2px，`text-underline-offset: 0.12em`                            |
| 波浪线 wavy      | 不填底；线用实色，粗 1.5px，`text-underline-offset: 0.16em`                          |

**PDF**：盖在渲染好的页面上，用图层透明度 35%，选中那条升到 55%。

**规则**

- 存储值始终是不透明十六进制；透明度只在渲染时加，数据不随主题变。
- 天蓝、青绿这类偏亮的颜色在浅色页面上可把透明度提到约 50%，其余维持 42%。
- 悬停与跳转反馈使用该记录自己的颜色，不用品牌色。

**Rationale** 用户划线是为了以后还能读，不是为了把句子涂掉。铺实色会压掉文字、行距和相邻内容；半透明让痕迹和文字并存。

- 等宽：`--myz-mono` = JetBrains Mono

**中文按语言选地区版本**，只加载当前语言那一套。下表的地区版本是规范目标。

| 界面语言        | `--myz-cjk`       | 说明                  |

### 3.6 布局与间距

**间距：基准 4，只有 6 档**

| 步进 | 用途 |
| ---- | ---- |
| 4 | 图标与文字之间、行内元素之间、pill 内边距 |
| 8 | 同一部件内相邻块（行内三段、按钮与计数） |
| 12 | 列表行左内边距（`--myz-row-pad-x`）、相邻部件之间 |
| 16 | 分组内边距、卡片内边距 |
| 24 | 区块之间（导航分组之间、页面段落之间） |
| 32 | 大区块之间（设置分组之间、空态上下） |

不允许 20 / 28 / 36 / 40 这类「看起来差不多」的档。实测旧实现 240 处间距用了 10 档，同一类组件在不同页面拿到不同值——这是「好几个面不像一套东西」的主要来源之一。

**这 6 档管的是布局**（区块之间、部件之间、行左右内边距）。**组件内部的固定尺寸由各自的组件规范定义**，不受 6 档约束，例如状态 pill 内边距 6、状态色条 3px、行内图标与文字间距 4——它们是组件自己的刻度，不是布局刻度。两者混在一起谈，就会出现「pill 为什么可以用 6」这种不必要的争论。

**工作区四区骨架（§4.27）**

| 区域 | 宽 | 可调 | 说明 |
| ---- | -- | ---- | ---- |
| 图标栏 rail | 48（`--myz-rail-w`） | 否 | 恒在，图标 20、命中 32，当前项左侧 2px 强调条 |
| 导航栏 nav | 240（200–320） | 是 | 分组导航 + 计数 pill + 拖拽投放目标 |
| 主区 | 自适应，最小 480 | 否 | 列表 / 正文；正文用 `.read-body` 38em 居中 |
| 右侧面板 panel | 280（260–380） | 是 | 详情 / 目录 / 大纲；默认收起，按需展开 |

- 拖拽手柄宽 4，命中区 12，`role="separator"` + `aria-valuenow`；`←/→` 调 8px，`Home` 复位，`Enter` 折叠。宽度写本地设置（不同步）。
- 工作区**不再给整页 `max-width`**。旧实现是 `max-w-[1400px]` 居中，1440 屏上四边全是空；列表和正文各自控宽，壳不控宽。
- 断点只用三档：**640 / 900 / 1200**（900 是全仓现有断点，不再引入 1024）。

| 视口 | 布局 |
| ---- | ---- |
| ≥ 1200 | rail + nav + 主区 + panel（panel 默认收起，展开占位） |
| 900–1199 | rail + nav + 主区；panel 改为覆盖式抽屉 |
| 640–899 | rail + 主区；nav 改为抽屉；行高升到触控档 64（`--myz-row-h-touch`） |
| < 640 | 单栏 + 底部导航（5 项：文库 / Inbox / 阅读 / 素材 / 设置） |

**浮层与固定宽（不属于工作区骨架，不许各页各写）**

| 区域 | 宽 | 说明 |
| ---- | -- | ---- |
| 浮动目录 §4.11 | 展开 200 / 收起 44 | 浮层，不占正文宽 |
| 批注浮层 §4.8 | 280 | 网页与 PDF 都是浮动 280 |
| 采集编辑弹窗 §4.8 | 320 | 样式 / 标签 / 调色盘 |
| 扩展弹窗 §4.21 | 360 | 系统面板 |
| 阅读器目录 / 标注侧栏 | 240 | PDF 与 EPUB 共用；阅读器不套四区骨架（见下） |

**阅读器不套工作区骨架**：PDF / EPUB 是「一个文档占满屏」，套 nav + panel 会把原页挤窄。阅读器只保留两样——可隐藏的 rail（返回工作区）与右栏 240（目录 / 批注 / 高亮）。原页舞台占满其余宽度。

**设置页**用四区骨架的退化形态：rail + nav（设置分组）+ 内容，无 panel；窄于 900 时 nav 收进抽屉。

**200% 缩放与窄屏重排**

- 页面放大到 200% 时：可调宽度失效（按 clamp 下限固定），nav 与 panel 改为抽屉，表单/PDF 顶栏不得横向溢出，长文本换行而不是撑破容器。
- 禁止用 `min-width` 写死整个页面；只有 PDF 原页舞台允许横向滚动。
- 字号用 rem 或 Token 值，不写死 px 让缩放失效；组件高度用 `--myz-hit-*`。

**Rationale** 分栏是为了同时看清两样东西——文库要并排「来源」与「记录」，Inbox 要并排「队列」与「这条写了什么」。旧壳是「居中 1400 宽的单列 + 顶部通栏」，看起来像一张居中的文档，而不是一个能干活的工作区；屏幕越大浪费越多。固定宽度表的作用是把「侧栏多宽」从每页自行决定变成查表——现在这四个区各有 token，拖拽边界也可查，不再出现 200/264/280/320 四种并存。

| 圆角 | Token      | 用在哪                                         |
| ---- | ---------- | ---------------------------------------------- |
| 4    | `--myz-r-xs`   | 色块、条形、行内小标记                         |

| 允许投影 | 不允许投影（用边框/底色分层） |
| -------- | ----------------------------- |
| 采集条、紧凑高亮条（固定深色，见 §4.7） | 记录卡 `HighlightCard` |
| 批注浮层 / Inspector | 分组容器、设置分组卡 |
| 弹窗、下拉菜单、搜索建议 | 面板外壳、页面侧栏、设置侧栏 |
| 浮动目录 | PDF 舞台里的原页（原页是原件，用页面抬升表达，见 §4.22） |
| 通知提示条 | 按钮、输入框、标签、列表行 |

深色模式靠"抬高底色 + 更清楚的边框"分层，不靠加重阴影。违反本表的实现按 B 类差异处理。

`--myz-shadow` 按方案与深浅色各一套：

| 方案    | light                                | dark                              |
| ------- | ------------------------------------ | --------------------------------- |
| paper   | `0 14px 36px rgba(20, 20, 19, 0.12)` | `0 16px 40px rgba(0, 0, 0, 0.45)` |
| slate   | `0 16px 40px rgba(15, 23, 42, 0.18)` | `0 16px 40px rgba(0, 0, 0, 0.4)`  |
| celadon | `0 14px 36px rgba(18, 30, 22, 0.12)` | `0 16px 40px rgba(0, 0, 0, 0.45)` |
| ochre   | `0 14px 36px rgba(35, 26, 18, 0.14)` | `0 16px 40px rgba(0, 0, 0, 0.5)`  |

采集条的边界例外，用固定值（深色投影 + 浅色描边），见 §4.7。

### 3.8 动效

| Token            | 时长        | 用在哪                       |
| ---------------- | ----------- | ---------------------------- |
| `--myz-motion-fast`  | 120ms       | 悬停变色、聚焦光圈、按钮反馈 |
| `--myz-motion-med`   | 180ms，缓出 | 采集条与批注面板淡入、提示条 |
| `--myz-motion-panel` | 240ms       | 侧栏、抽屉、目录收合         |
| —                | 不动        | 正文与 PDF 页面内容          |

**组件到档位的映射**

| 组件 | 用哪档 | 动什么 |
| ---- | ------ | ------ |
| 按钮 / 图标按钮 / 链接 | fast 120ms | 底色、边框、文字色 |
| 输入框 / 下拉项 | fast 120ms | 边框、聚焦光圈 |
| 采集条、紧凑高亮条 | med 180ms 缓出 | 淡入（可带 ≤4px 位移） |
| 批注浮层 / Inspector | med 180ms 缓出 | 淡入 |
| 通知提示条 | med 180ms 缓出 | 淡入 + 上移，自动消失前可淡出 |
| 侧栏 / 抽屉 / 浮动目录 | panel 240ms | 宽度或位移，箭头方向 |
| 卡片列表出现 | 不动（直接出现） | 不做逐条入场 |
| 正文与 PDF 页面 | 不动 | 一律不加动画 |

- 跳到某条划线时，用该条自己的颜色闪一下，约 1 秒（记录色，不用品牌色）。
- 系统开启「减少动态效果」时，去掉位移，淡入 ≤ 120ms；骨架微光停止。
- PDF 阅读器必须同样处理 reduced-motion（当前缺失）。

### 3.9 无障碍

| 方面     | 要求                                                                    |
| -------- | ----------------------------------------------------------------------- |
| 对比度   | 正文、次要文字、链接、按钮文字 ≥ 4.5:1；四种方案 × 深浅色共八套全部通过 |
| 聚焦     | 每个可点元素有可见聚焦圈，用强调色 2px，偏移 2                          |
| 点击范围 | 桌面 ≥ 32×32，手机 ≥ 44×44                                              |
| 动效     | 尊重 `prefers-reduced-motion`                                           |
| 颜色之外 | 高亮不能只靠颜色区分，配合下划线、波浪线或左侧色条                      |
| 文字缩放 | 放大到 200% 时布局不破、内容不丢                                        |

**命中区的实现口径**：桌面所有可点元素的实际命中区 ≥ 32×32，用 padding 或透明的 `::before` 外扩，不用可见尺寸硬撑。卡片操作、删除、关闭、PDF 侧栏关闭、目录折叠箭头都必须外扩到 32。手机用 `--myz-hit-touch` 44。

**文字缩放的做法**：字号优先用九级 Token / rem，容器用 `max-width` 而不是 `width`，侧栏与弹窗在窄屏可折叠，避免 200% 下横向滚动。PDF 原页舞台允许横向滚动是唯一例外。

## 4. 组件

组件按"原子 → 布局/复杂 → 交互"排列：§4.1–4.16 是跨宿主的基础组件与规则；§4.17–4.22 是按场景补齐的设置、内容层、列表/侧栏、弹窗与 PDF 组件。密度由 `--myz-hit-*` 决定：紧凑 32 / 常规 36 / 触控 44。字号一律查 §3.5 的映射表，动效查 §3.8。

### 4.1 图标

- 来源：Lucide（MIT），只描边不填充，线宽 1.75，圆角端点。
- 尺寸：默认 16，36px 按钮里 20，手机 24。
- 点击范围：图标周围至少 32×32。

### 4.2 圆角

见 §3.7。所有取值从 `--myz-r-*` 取。

### 4.3 卡片

记录卡是一张纸片，不是仪表盘小部件。

| 属性       | 做法                                                           |
| ---------- | -------------------------------------------------------------- |
| 外观       | `--myz-surface` 底，1px `--myz-line` 边框，圆角 `--myz-r-lg`，内边距 12–16；**不加阴影** |
| 类型标签   | 标签 chip：高 22、界面字体 11/600、`--myz-tag-bg`/`--myz-tag-fg`；摘录用 `--myz-clip-bg`/`--myz-clip` |
| 引用与批注 | 长文字体 14–16，行高 1.55–1.6                                  |
| 来源行     | 界面字体 11，`--myz-muted`；来源截断最多约 120px，用 title 补全    |
| 正文限高   | `max-height: 20lh`，超出后卡片内部滚动                         |
| 页码徽标   | 高 20–22 的 pill，`--myz-warn-bg`/`--myz-warn`，文案「第 N 页」    |

**类型标签定稿**：标签只是标记，颜色由 §4.5 的 `--myz-tag-*` 决定，不再用 §旧文的 `--myz-accent-text`；摘录用 `--myz-clip-*`。卡片、Popup、PDF 标注行、查看器四处一致。

`20lh` 用行高作单位：换方案或调阅读字号时上限跟着字体缩放，不会出现小字卡片很高、大字卡片装不下的情况。

### 4.4 按钮

| 属性     | 做法                                              |
| -------- | ------------------------------------------------- |
| 高度     | 28 / 32 / 36 / 44（§2.5 四档），左右内边距 12     |
| 文字     | 界面字体 13，字重 600                             |
| 圆角     | `--myz-r`（8），**不用胶囊**；胶囊只给采集条与分段控件 |
| 底色     | `--myz-control-bg`，边框 `--myz-control-border`           |
| 主按钮   | 实心 `--myz-accent`，文字 `--myz-on-accent`；一屏只有一个 |
| 危险操作 | 文字色 `--myz-error`，不用实心红                      |
| 聚焦     | 强调色 2px 外圈，偏移 2，必须 `:focus-visible`，不许去掉 |
| 禁用     | 整体透明度 45%，文字颜色不变；不用 40/60 等另一套值     |

**图标按钮**：正方形，命中区 ≥32；在紧凑行内允许 28（`--myz-hit-dense`），此时图标 16。放在 36 的按钮行里时可见尺寸 32，图标 18。弹出菜单里的图标按钮跟随选项行高。

**例外**：分段控件（§4.19）与浮动工具条（§4.7/§4.18）用胶囊；分段控件的当前项用实心强调色，其余选中态见 §4.10。

### 4.5 标签

| 属性       | 做法                                          |
| ---------- | --------------------------------------------- |
| 尺寸与文字 | 高 22，界面字体 11，字重 600                  |
| 颜色       | `--myz-tag-bg` / `--myz-tag-fg`，实色，不用半透明叠加 |
| 输入       | 回车生成一个标签，不解析逗号字符串            |

标签只是标记，不是集合。颜色留给划线色板。

### 4.6 输入框

| 属性 | 做法                                       |
| ---- | ------------------------------------------ |
| 高度 | 单行 36（紧凑 32），圆角 `--myz-r`             |
| 字体 | 搜索与设置用界面字体；批注用长文衬线       |
| 标签 | 界面字体 12，`--myz-muted`，距输入框 6；**不大写、不加字距** |
| 聚焦 | 边框变 `--myz-accent`，外加 3px 20% 强调色光圈 |
| 禁用 | `--myz-surface-2` 底，文字仍清晰               |

**原生控件的统一外形**（下拉、日期、文件，形状与输入框一致）

| 控件 | 做法 |
| ---- | ---- |
| `<select>` | 同输入框高度/圆角/边框/底色；右侧留出原生箭头空间，不自绘箭头；聚焦光圈同输入框 |
| `<input type="date">` | 外层用同输入框的容器包住，日历图标用 Lucide `Calendar` 放在行尾触发 `showPicker()`；隐藏 WebKit 默认日历图标 |
| `<input type="file">` | 用同输入框的容器；文件名文字用 `--myz-text` 截断，右侧一个 `--myz-r` 的按钮触发选择；不用浏览器默认样式 |
| 紧凑场景 | PDF 侧栏搜索框高 32，圆角 `--myz-r`，聚焦光圈同规则 |

### 4.7 采集条

选中文字后浮出的工具条，是采集唯一的入口。

| 属性        | 做法                                            |
| ----------- | ----------------------------------------------- |
| 形态        | 胶囊，图标 32，间距 4，跟随选区，层级最高       |
| 底色        | 固定 `--myz-overlay`（`#141413`），不跟方案与深浅色 |
| 文字 / 图标 | `--myz-overlay-text`                                |
| 边界        | 深色投影 + 1px 浅色描边（见下）                 |
| 高度        | 紧凑                                            |
| 动作        | 划线、摘录、截取、搜索；阅读器内另有「翻译」     |
| 子按钮      | 32×32，圆角 `--myz-r-pill`（固定深色工具条的例外），图标 16 |
| 悬停 / 聚焦 | 悬停 `--myz-overlay-hover`；聚焦 `--myz-overlay-text` 2px 外圈 |
| 动效        | 只做底色淡入（fast）；**不做 `scale` 缩放**，§2.8 只解释变化 |

**为什么固定深色**：它出现在任何网页上，无法知道自己压在什么背景上。固定深色在哪都稳定。深色页面上靠一圈约 16% 白的 1px 描边勾出轮廓，浅色页面上靠普通深色投影浮起——两样同时写在 `box-shadow` 里，互补：

```css
box-shadow:
  0 8px 24px rgba(0, 0, 0, 0.35),
  0 0 0 1px rgba(255, 255, 255, 0.16);
```

**阅读器与网页内的翻译**：PDF / EPUB 采集条和网页采集条都在划线、摘录之外多一个「翻译」（§4.24），放在截取与搜索之间。整本书的翻译不挤进采集条，而是由阅读器顶栏的「对照翻译」（§4.26）开一个并排译文栏。跨域宿主页的 `Permissions-Policy` 可能禁用端上模型，此时按不支持给出明确文案，不报错。

**Rationale** 采集条是临时的操作层，不是用户的阅读环境；固定深色让它在任何页面上都保持同一个熟悉的样子，也与 §2.3 一致。

### 4.8 弹窗和浮层

| 属性     | 做法                                                            |
| -------- | --------------------------------------------------------------- |
| 采集编辑弹窗 | 宽 **320**，`--myz-surface` 底，圆角 `--myz-r-lg`，带阴影；装样式 / 标签 / 调色盘 |
| 批注浮层 | 宽 **280**（网页与 PDF 一致；内容与行为见 §4.18）               |
| PDF 批注栏 | 浮动 **280**（与网页一致）                                       |
| 长文阅读 | 走查看器页面，不用大模态                                        |
| 遮罩     | 只有居中、会丢数据的确认类对话框才加不透明遮罩；采集小卡片不加 |
| 透明层   | **允许**用一个透明的全屏层来居中、承接"点外侧关闭"；它本身不画底色、不模糊背景 |
| 关闭     | Esc 关闭；点外侧只关不会丢数据的；关闭按钮用 Lucide `X`，不用 `×` 字符 |
| 聚焦     | 打开时落到第一个输入框，关闭后回到触发按钮；对话框边界加 `role="dialog"` `aria-modal` |
| 扩展弹窗 | 360 宽，属于系统面板，不是对话框组件（见 §4.21）                 |

**宽度定稿**：批注浮层（只读/就地编辑）统一 **280**；采集编辑弹窗（有样式、标签、调色盘）用 **320**；不再出现 240 / 300 / 其他值。

**`RecordModal` 并入查看器**：记录的长文阅读与编辑一律走查看器页面，不再保留大对话框。查看器承担原文还原、下一条/上一条、编辑批注与标签；不再出现 `max-w-5xl` 全屏遮罩式弹窗。关闭图标若仍需在别处出现，用 Lucide `X`，不用 `×` 字符。

### 4.9 卡片瀑布流

文库的记录列表。

| 属性     | 做法                                                  |
| -------- | ----------------------------------------------------- |
| 列数     | 窄屏 1，中等 2，宽屏 3                                |
| 间距     | 列间距与行间距都用 12                                 |
| 卡片高度 | 跟内容走，不裁成等高；正文限高 `20lh`，超出后内部滚动 |
| 排序     | 按"时间"或"文中顺序"                                  |
| 加载     | 优先渲染第一屏，后续懒加载                            |

> **0.7 待定（待用户拍板）**：flush 行成为默认列表后，卡片瀑布流还留不留。当前按「留」写——它适合长短差异大的长文摘要，flush 行适合扫视。若砍，本节与 §6 的「卡片瀑布流」一起删，列表行成为唯一视图，`HighlightCard` / `HighlightGroups` / `HighlightsPaneShell` 三个组件一并退场。判据：用户实际用不用第二视图；没人切就是砍。

**Rationale** 记录长短差别大，等高网格会给短记录留大块空白。

### 4.10 菜单和目录的层级

| 问题     | 做法                                                       |
| -------- | ---------------------------------------------------------- |
| 从属关系 | 子项缩进 12–16，字号小一档或颜色更淡，不画引导线           |
| 分组     | 组标题用 10 号大写字加 `--myz-muted`；组之间一条细线，不用空行 |
| 层叠深度 | 最多两层（组 → 项）。需要第三层时改为跳到单独面板          |
| 重点     | 当前项用"浅底 + 强调色文字"，不用实心填充；次要信息靠右    |
| 可折叠   | 折叠箭头放最左，点标题整行展开；展开状态记在本地                |
| 长目录   | 与正文滚动联动、当前节高亮；不自动滚动抢位置                    |

**选中态统一口径**

- **列表项、导航项、目录项、侧栏项、设置导航项**：当前项用「`--myz-surface-2` 浅底 + `--myz-accent-text` 文字 + 600 字重」，不用实心强调色填充。
- **分段控件与分页**：当前项属于紧凑控件而非列表项，用实心 `--myz-accent` + `--myz-on-accent`（见 §4.19）。
- 不允许出现第三种：半透明强调底 + 强调色边框的写法只在弹出/选中卡片（如配色方案选择、PDF 标注项）使用，且必须同时有强调色文字。

**分支图标**：目录/菜单里表示展开折叠的箭头用 Lucide `ChevronDown`/`ChevronRight`，图标按钮命中区 ≥32。

### 4.11 浮动目录

PDF 阅读器和长文查看器共用。

| 属性       | 做法                                                        |
| ---------- | ----------------------------------------------------------- |
| 两种状态   | 展开 200px，收起 44px；收起只留一个按钮                     |
| 位置       | 固定在左侧，垂直居中；正文外侧有余量时展开                  |
| 与主体关系 | 浮在内容之上，不改变正文宽度，展开收起时正文不跳动          |
| 滚动联动   | 正在读的一节自动高亮                                        |
| 点击       | 跳到对应位置；PDF 里跳到对应页                              |
| 动画       | 240ms 收合，只改宽度与箭头方向                              |
| 窄屏       | 默认收起；展开时盖住内容、点外部关闭                        |
| 滚动       | 面板自身滚动，必须能收住高度（flex 子项需 `min-height: 0`） |

**Rationale** 目录是"路过看一眼"的东西，不该常驻占掉正文宽度。

### 4.12 下拉菜单

| 属性   | 做法                                                                   |
| ------ | ---------------------------------------------------------------------- |
| 面板   | `--myz-surface` 底，圆角 `--myz-r-lg`，边框 `--myz-control-border`，阴影与弹窗同源 |
| 选项   | 高 32，圆角 `--myz-r-sm`，左右内边距 10                                    |
| 当前项 | 浅底加重，左侧可能出现对勾；不用纯色填充                               |
| 分组   | 组标题 10 号大写字；组之间一条细线                                     |
| 长列表 | 最高约 224，超出后滚动                                                 |
| 键盘   | 上下移动，回车确认，Esc 关闭且焦点回触发按钮                           |

### 4.13 搜索建议

输入 `#` 找标签，输入 `site:` 找网站。

| 属性   | 做法                                                 |
| ------ | ---------------------------------------------------- |
| 触发   | 输入框有焦点且已有输入时出现；也可点右侧按钮展开全部 |
| 每行   | 左类型标签，中内容，右可留类别                       |
| 排序   | 全等 → 前缀匹配 → 包含匹配；同分按字母序             |
| 上限   | 最多 10 条                                           |
| 选择   | 填入 `#标签` 或 `site:网站` 并关闭                   |
| 键盘   | 同下拉菜单                                           |
| 空结果 | 不弹面板                                             |

### 4.14 调色盘

用户自己改的五个划线颜色，采集浮层与设置页共用。

| 属性     | 做法                                          |
| -------- | --------------------------------------------- |
| 色块     | 直径 32，间距 8，居中                         |
| 选中态   | 外圈一圈 `--myz-text` 的环，不用对勾              |
| 改色入口 | 每个色块角上一支小铅笔，点开系统取色器        |
| 默认色   | 单独一行显示当前默认值的色块与色号            |
| 恢复默认 | 一个按钮复位全部五个颜色                      |
| 无障碍   | 每个色块有可读名字（琥珀、珊瑚…），不只报色号 |

**Rationale** 调色盘是记录数据的一部分，交互要稳：选中和编辑分开，点一下只做一件事。

### 4.15 空、加载、出错

**状态必须按它实际出现的位置呈现**，不是一律塞一个灰框：可以是整页、整面板、卡片内、列表内一行。

| 情况        | 做法                                                    |
| ----------- | ------------------------------------------------------- |
| 空          | 一个图标（Lucide，22–24）+ 一句状态 + 一句下一步，不写"无数据" |
| 加载        | 与内容同高的骨架条，颜色走 `--myz-skeleton`；可加很淡的微光（reduced-motion 时停） |
| 出错        | 错误色图标 + 说明可能原因 + 一个重试或替代动作（按钮）  |
| 成功 / 提示 | 提示条贴近操作位置，几秒后自动消失                      |

**状态组件的形态**

| 属性 | 做法 |
| ---- | ---- |
| 骨架条 | 圆角 `--myz-r-sm`；高度按行高取（正文行 12–14）；一组 2–3 条，宽度错落（70% / 45%） |
| 空状态图标 | `--myz-muted`；出错图标用 `--myz-error`；尺寸 22–24 |
| 文案 | 一句状态（正文级）+ 一句下一步（说明文字级），都不加句号客套 |
| 错误重试 | 次要按钮（§4.4），紧贴错误文字下方，不要跳走 |
| 提示条 | 底色固定 `--myz-overlay`、文字 `--myz-overlay-text`，圆角 `--myz-r`，内边距 12/14，最大宽 280 |
| 提示条位置 | 普通提示贴近触发的操作（采集条与阅读器在右上；设置留在操作行尾的 `.status-line`，不浮起）。**带撤销的破坏性动作落在哪，不由本节决定，见 §4.30 的「作用范围」表**；同一时刻同一件事只出现一处 |
| 提示条时长 | 普通提示 3–4 秒（默认 4 秒）；带撤销动作的提示 6 秒（落位见 §4.30），悬停或聚焦时暂停倒计时，点击动作后立即结束；可堆叠但最多 3 条，新的在下方，旧的先消失 |
| 提示条动作 | 默认不带按钮；确需「撤销」时给一个文字动作，点击后立即消失；一条提示只带一个动作 |

设置页的行内反馈用 `.status-line`（主题文本色：`--myz-muted`/`--myz-error`/`--myz-success`），不用固定深色 toast；跨页面、会浮起的通知才用 `--myz-overlay`。

### 4.16 专注阅读和重排

（在展示页里与"阅读字号五档"一起放在"字体与排版"一节。）用于我们自己保存的文字与 HTML 文章，不适用于 PDF 原页和网页上的划线。

| 属性   | 做法                             |
| ------ | -------------------------------- |
| 字体   | `--myz-read`                         |
| 字号   | `--myz-read-size-1…5`，默认第三档 18 |
| 行距   | `--myz-read-leading`，默认 1.8       |
| 字间距 | `--myz-read-tracking`，默认 0.01em   |
| 栏宽   | `--myz-read-measure`，默认 38em      |
| 页边距 | `--myz-read-gutter`，默认 24         |
| 纸色   | **跟随配色方案与深浅色**（不写死浅色） |
| 外框   | 只留退出与排版控件               |

**本期不做字号切换控件**：专注阅读后续会整体重做，所以这版只保证纸色跟随方案与深浅色、排版按五档默认值渲染；字号/行距/栏宽的调节控件留到重做时一起做。

**Rationale** 字号、行距、字间距、栏宽、页边距全部变量化，用户能调，未来 EPUB 直接复用同一套。PDF 走"原页 + 缩放 + 坐标标注"，与这套无关。

### 4.20 记录列表行、来源侧栏与导出

**列表视图行 `HighlightListRow`（flush 行，不是卡片）**

| 属性 | 做法 |
| ---- | ---- |
| 容器 | **无卡片**：无独立边框、无圆角、无行间隙；行高 `--myz-row-h`（56），上下内边距 8、左右 `--myz-row-pad-x`（12），底 `--myz-surface` |
| 分隔 | 相邻行之间 1px `--myz-line` 分隔线（用上一行的 `border-bottom`，末行不加）；列表整体可以有一条外框，行内不再重复 |
| 左色条 | 3px 宽、圆角 `--myz-r-xs`，用记录自己的颜色；摘录用 `--myz-clip` 虚线 |
| 行内结构 | 三段：主文本 14 单行截断 + 次要行 12（来源 · 时间）+ 行尾元信息（页码、标签 `+N`） |
| 动作 | **不常驻**：hover、键盘聚焦或选中时才出现；触屏（< 640）常驻。动作按钮 28，图标 16 |
| 悬停 / 选中 | 悬停 `--myz-surface-2`；选中 `--myz-surface-2` + 左色条换成 `--myz-accent` |
| 行间距 | 无（0）。要更松用 `--myz-row-h` 换档（§2.5），不加间隙 |

**为什么不是卡片**：几千条的列表里，每行一张带边框圆角的卡片 + 12 行间隙，一行实际占 140–160，而内容只有 56 的必要高度——800 高的列表区只放得下 5 行。§2.6 自己写着「到处加圆角会让文库看着像数据管理工具」。卡片留给真正独立的东西：空态、设置分组、快照正文。**行只有一条分隔线。**

**来源侧栏**

| 属性 | 做法 |
| ---- | ---- |
| 宽 | 240（§3.6，不再是 240–280 两值并存）；`--myz-surface`、右侧 1px `--myz-line`、内边距 12；按 §3.7 不加阴影 |
| 头 | 标题 14/600 + 排序说明 12 |
| 项 | 行高 32（与 §4.27 的 nav 项同一档；40 的紧凑行只用于表格与素材标题行）；标题 13/600 单行截断 + host 12 + 计数 pill 11；当前项按 §4.10 |
| 收起 / 页面筛选 | 一个 28 的按钮；筛选 chip 高 22、最大宽 180 截断 |
| 空态 | §4.15 |

**导出入口与菜单**：入口是普通按钮（`--myz-r`，不是胶囊），右侧 `ChevronDown` 图标（不用 `▼` 字符）；菜单完全复用 §4.12（面板 r-lg、选项 32/r-sm、Lucide 图标、Esc 与焦点回位）。

| 属性 | 做法 |
| ---- | ---- |

### 4.23 表单与字段

§4.6 定义单个输入框，§4.17 定义设置分组；这一节定义表单本身的布局、状态、校验与输入组。

**布局**

| 场景 | 做法 |
| ---- | ---- |
| 单行（默认） | 左 label、右控件，`justify-between`；控件宽 288，简单项一行一个，最省纵向空间 |
| 纵向 | 控件需要整行时用：文本域、标签输入、调色盘、方案卡、文件选择、长文本 |
| 分组 | `--myz-surface` 卡片 + 1px `--myz-line` + 圆角 `--myz-r-lg` + 内边距 16；组内行距 16；组标题 17/600 |
| 多列 | 表单列最窄 280；容器窄于「2×列 + 间距」时降为单列；同一行不超过两列 |
| 窄屏 | 容器窄于 640 时，单行布局降为纵向（label 在上） |
| 日期区间 | 两列 + 中间连接符，不拆成两行 |

**标签与帮助**

- label 用界面字体 13（`--text-label`）或 12，**正文色**（不是 `--myz-muted`，保证可读）；距控件 6。
- 可选字段标「可选」；不要给必填字段加星号再配复杂说明。
- 帮助文本用说明文字级 `--myz-muted`，放在控件下方；错误文本替换帮助文本的位置，不叠加。
- label 必须关联控件（`<label for>` 或包裹）；一组相关控件用 `<fieldset>` + `<legend>`。
- 不用 placeholder 当唯一标签。

**字段状态**

| 状态 | 做法 |
| ---- | ---- |
| 默认 | `--myz-control-bg` 底 + `--myz-control-border` 边 |
| 悬停 | 边框转强调色边（可选） |
| 聚焦 | 边框 `--myz-accent` + 3px 20% 强调色光圈（§4.6） |
| 已填写 | 值用 `--myz-text` |
| 禁用 | 整体 45%，不响应交互 |
| 只读 | `--myz-surface-2` 底、文字仍清晰、可选中 |
| 错误 | 边框 `--myz-error`，下方错误文字 12、`--myz-error` |
| 成功 | 用行内状态文字（§4.15），**不给字段加绿框**，避免与错误并存时歧义 |

**校验与反馈**

- 就地提示在字段下方，不用 toast；提交失败时聚焦第一个错误字段。
- 错误文案说清怎么改，不写「非法输入」。错误源和控件用 `aria-invalid` + `aria-describedby` 关联。
- 提交中：主按钮禁用 + 「保存中…」；成功后行内状态文字说「已保存」（§4.17），不用固定深色提示条。
- 破坏性动作（删除、重置）放次位；删除用文字 `--myz-error`，不实心红。

**输入组**

- 日期：外层同输入框容器，行尾 Lucide `Calendar` 触发 `showPicker()`，隐藏 WebKit 默认图标。
- 文件：隐藏原生 input（`sr-only`），用一个 control 按钮 + 文件名（截断、`--myz-caption`）组成整组，整组可点。
- 前缀 / 单位：前缀用 `--myz-muted` 文本置于控件左侧，不单独做标签。
- 搜索：单行、圆角 `--myz-r`、聚焦 3px 20% 光圈；尺寸走 `--myz-hit-*`。

**无障碍**

- 每个控件有可读 label；必填 `aria-required`；错误 `aria-invalid` + `aria-describedby`。
- 支持浏览器自动填充而不破版；`autocomplete` 语义正确（如 `email`、`current-password`）。

**Rationale** 表单是最容易出现"每个页面一套"的地方：标签时而上时而下、错误提示时而 toast 时而红框、下拉时而原生时而定制。把布局与状态收敛成一条规则（简单项左右、复杂项纵向、错误就地、提交用行内状态），新加一个设置项就是套模板，不用再讨论。

### 4.24 翻译浮层

选中文字后点采集条上的「翻译」，在选区附近浮出的只读结果面板。端上模型完成翻译，内容不出设备；译文可复制。段落结构**取自文档本身**（HTML/EPUB 按块级元素切分，PDF 按几何分行分段），不是靠换行猜测，逐段翻译后再拼回，所以原文与译文都保持段落结构。PDF、EPUB 与网页采集条共用同一个组件（样式在共享 `translation-popover.css`）。

| 属性 | 做法 |
| ---- | ---- |
| 形态 | 宽 `min(400px, 100vw - 32px)`，`--myz-well-chrome` 底、1px `--myz-well-border`、圆角 `--myz-r-lg`、`--myz-shadow`；`role="dialog"` |
| 定位 | 锚在选区下方居中（`translateX(-50%)`）；下方空间不足时翻到选区上方；上下左右都限制在视口内，整体最高 `min(60vh, 560px)`，长文在面板内滚动，不遮住整页 |
| 拖动 | 按住头部可拖动（头部 `cursor: grab`，拖动中 `grabbing`）；拖动后仍限制在视口内 |
| 内容 | 头（`Languages` 图标 + 「翻译」+ 语言对 + 关闭 `X`）、原文引用、状态、译文、动作 |
| 原文引用 | 左侧 3px 强调色，`--myz-surface-2` 底，长文衬线 14，保留换行（`pre-wrap`）；最高 **5 行**，超出在框内滚动，避免原文挤占译文 |
| 语言对 | 「检测到的源语言 → 目标语言」，界面字体 12，`--myz-well-muted`；检测中显示「检测中」 |
| 译文 | 长文衬线 14、行高 1.7、`pre-wrap`，与原文同一滚动区；按段翻译并保留段落结构（段间空行） |
| 状态 | 识别中 / 下载语言包（带 0–100% 进度条 `--myz-accent`）/ 翻译中；无静默失败 |
| 出错 | 文案 `--myz-error`，给出「重试」；源=目标、暂不支持、超配额、不支持浏览器各有明确文案 |
| 动作 | 「复制」（主按钮，成功后短暂变「已复制」）；出错时「重试」；进行中可「取消」 |
| 动效 | 淡入 med 180ms 缓出（§3.8）；进度条宽度 fast；拖动时不动画；尊重 reduced-motion |
| 无障碍 | 打开聚焦浮层；Esc、点外侧、关闭按钮都关闭；关闭后回到触发按钮；进度用 `role="progressbar"` |
| 缓存 | 译文按 `源:目标:文本哈希` 存本机：阅读器用 `myz_translate_db`，网页内容层用扩展 `chrome.storage.local`（content script 的 IndexedDB 属于宿主页 origin，不能用）；都不同步、不出设备 |

**Rationale** 翻译是阅读中的一个临时动作，和批注一样「看一眼就走」，所以沿用浮层而不是页面或大模态；只读、不写回记录，因此没有编辑区。端上模型需要下载语言包，进度、取消与出错必须当场说清楚，否则用户会以为按钮坏了。

### 4.25 Inbox 队列组件

Inbox 是新采集内容的处理队列，不是文库副本，也不是按时间、主题或页面重排的发现页。它消费同一组 `MyZRecord`，但额外显示用户工作流状态。保留、归档、删除和编辑的权威结果必须能回到文库。

**页面骨架**

| 组成 | 做法 |
| ---- | ---- |
| 导航 | 顶层独立项「Inbox」；文库仍叫「文库」；Inbox 已实现（见 §5.6） |
| 左侧栏 | 走 §4.27 四区骨架的 nav（240，可拖 200–320）：队列状态导航（待处理/稍后处理/已标记）+ 标签列表；标签为拖拽投放目标（拖记录上去即打标签），点击标签筛选队列；窄屏收进抽屉 |
| 页面头 | 走 §4.27 的 header（48 吸顶）：标题 Inbox 17/600 + 「待处理 N 条 · 最早积压 X」的计数说明 12；右侧搜索（32）+ 视图切换 + 专注 |
| 状态筛选 | 在 nav 里：待处理（默认）/ 稍后处理 / 已标记；不使用“时间 / 主题 / 页面”作为主导航 |
| 搜索 | 高 32、圆角 `--myz-r`，搜索正文、批注、标题、标签和来源 |
| 批量工具 | 选择框 + 批量保留、归档、稍后、删除；批量条按 §4.28，未选中时不出现、不占高 |
| 内容 | **单栏 flush 队列**（§4.20），行高 56、行间 1px 分隔、无卡片；选中项对应右栏详情 |
| 右侧面板 | 走 §4.27 的 panel（280，可拖 260–380）：选中一行的详情（原文、批注、标签、来源、同页记录入口）。窄于 1200 改为覆盖式抽屉 |
| 窄屏 | nav 收进抽屉；行高升到触控档 64（`--myz-row-h-touch`）、动作常驻；右栏改为底部抽屉 |

**InboxRecordRow**

| 属性 | 做法 |
| ---- | ---- |
| 命中区 | 行高 `--myz-row-h`（56）、左右 `--myz-row-pad-x`（12）；选择框 16（命中区 32）、动作按钮 28；不能用整行 button 包含多个按钮 |
| 内容顺序 | 选择框 + 状态色条 + 类型 chip + 状态 pill + 主文本单行 + 来源·时间 12 |
| 元信息 | 页码、章节、语言、内容长度和 enrichments 状态用 12 `--myz-muted` |
| 正文 | 主文本 14 单行截断（悬停 `title` 看全文）；展开阅读在右栏，不在行内长成 2–4 行 |
| 状态 | `pending` 用提示色，`snoozed` 用中性色，`marked` 使用标记图标与文字，不仅依赖颜色；pill 走 §4.29 |
| 动作 | 标记、保留、稍后、归档、删除；**hover / 聚焦 / 选中时出现**，触屏常驻；删除用危险文字按钮，不使用实心红色 |
| 数据边界 | 摘录、标题、来源来自原始记录；关键词、代表句和重复候选明确标为自动信息，不写回用户标签 |

**InboxEnrichmentPanel**

| 属性 | 做法 |
| ---- | ---- |
| 关键词 | 2–5 个 chip，复用 §4.5 尺寸但不等同于用户标签；点击可查看命中原句 |
| 代表句 | 直接引用原文 1–3 句，左侧使用 `--myz-info` 3px 条；显示来源，不叫“AI 摘要” |
| 重复提醒 | 使用「可能重复」/「已有相似记录」提示；展示候选记录和相似原因，不自动合并或删除 |
| 来源上下文 | 同 URL、同 PDF 页、同 EPUB 章节的记录数量与入口；不替代文库来源侧栏 |
| 计算状态 | 处理中、已完成、已跳过、失败都就地显示；失败不阻塞队列动作 |
| 隐私 | enrichments 在本地可重建，不默认同步；设备间可能暂时不同，文案必须说明“本机分析” |

**InboxStatusPill**

| 状态 | 文案 / 视觉 |
| ---- | ---------- |
| `pending` | 「待处理」，使用 `--myz-info-bg` / `--myz-info` |
| `snoozed` | 「稍后处理」，使用 `--myz-surface-2` / `--myz-muted`，显示到期时间 |
| `kept` | 「已保留」，只在处理反馈或文库筛选中显示，不留在默认队列 |
| `archived` | 「已归档」，使用中性色；归档仍可在文库筛选、搜索和导出中找到 |
| `marked` | 「已标记」或标记图标；它是独立标记，不改变状态 |

**右侧详情面板（替代旧「底部抽屉」）**

- 走 §4.27 的 panel：280（可拖 260–380），默认收起；选中一行即展开，切换行只换内容不动宽度。窄于 1200 改为覆盖式抽屉，窄屏改为底部抽屉（沿用 §4.8 的浮层、焦点和 Esc 规则）。
- 内容顺序：原始摘录（`--myz-read` 14/1.55）→ 批注 → 标签 → 来源与时间 → 同页/同来源的其他记录。自动 enrichments 排在用户内容之后。
- 表头一行：类型 11 + 状态 pill 11 + 关闭按钮 28。
- 编辑正文、批注和标签跳转到现有查看器，不在 Inbox 复制编辑器。
- 保留入文库后回到文库记录；归档后显示“可在文库的归档筛选中找到”。

**为什么从底部抽屉改成右栏**：「连续处理队列」时，用户对下一条的默认动作是「扫一眼再决定」。底部抽屉遮住队列下半屏，每看一条都要开关一次；右栏占掉 280 宽但队列仍可见，处理节奏不被打断。代价是 < 1200 时抽屉恢复——那是空间不够时的正确妥协。

**Rationale** Inbox 的价值是把“刚采集”和“确认保留”分开，并让用户能快速完成决定。自动信息只能减少判断成本，不能增加一个不可解释的自动分类系统。队列动作必须先于 enrichments 可用，模型或本地索引失败不能把用户锁在 Inbox 里。

### 4.26 对照翻译（双语并排）

读整本书时的翻译形态：顶部工具栏开启后，原文与译文并排，垂直位置对齐；只翻译**视口内完整可见**的段落，滚动继续，已译段落复用内存与本地缓存。PDF 与 EPUB 共用同一个调度核心与译文块排版，只在几何测量上不同。

| 属性 | 做法 |
| ---- | ---- |
| 入口 | 顶栏右侧（PDF 在缩放之后、EPUB 在进度之后）：`Languages` 图标 + 「对照翻译」。**首次**点击打开语言菜单（没有记忆语言），选定后按钮直接开启/关闭；开启后变「关闭翻译」。右侧 28 宽的 `ChevronDown` 拆分按钮是唯一换语言入口 |
| 语言菜单 | 宽 `min(272px, 100vw-24px)`、`--myz-well-chrome` 底、圆角 `--myz-r-lg`、`--myz-shadow`，按钮下方 6；分「原文语言（自动检测）」与「目标语言（9 种，两列）」；已选目标 `Check` + 强调色加粗；底部状态（识别中 / 准备语言包 % / 已译 N 段）与错误行 + 重试 |
| 原文语言 | 固定自动检测；检测到后括注（如「自动检测（英语）」），点该行即「重新检测」并重译当前目标 |
| PDF 版面 | 每页一行：原页 + 同宽译文页；开启时按「两列同屏」自适应缩放，关闭恢复原缩放。译文块用**固定页内坐标**（`left/top/width` 取源段落）：宽度最多扩到同带邻居左界，纵向槽位取同带下一块 `top`；超槽时按比例缩字号（下限 0.62×、绝对 ≥9px），不挪动位置，因此双栏、侧栏、图注、图旁标签保持交错 |
| EPUB 版面 | 舞台左右各半：章节 iframe + 镜像列；镜像列用文档坐标定位段落、随 iframe 滚动做 `translateY`，因此逐段对齐且滚动同步。右列没有滚动条，`wheel` 转发给章节 iframe（含 line/page 单位），滚右列即滚原文并继续翻译 |
| 译文块 | 长文衬线，字号取源段落行高（PDF）或章节字号（EPUB）；短块（标题、段末行）宽度补到页面文字列宽的 3/4，但不超过同带邻居，避免被自身宽度折行或压到隔壁栏 |
| 待译态 | `data-state="pending"` 的浅色流光条（1.2s 线性循环），译文到达即替换为正文；整批失败时回到空白并配合错误条，不留「一直在加载」的假象 |
| 出错 | 菜单关闭时按钮下方浮出错误条（最长 320、单行省略）+ 重试；打开菜单时错误行在菜单底部。同语言、暂不支持、不支持浏览器各有明确文案 |
| 动效 | 菜单淡入 + 上移 4（med 缓出，§3.8）；流光 1.2s linear；尊重 reduced-motion |
| 无障碍 | 按钮 `aria-haspopup="menu"` + `aria-expanded`；选项 `role="menuitemradio"` + `aria-checked`；Esc 与点外侧关闭；错误用 `role="alert"` |
| 缓存与偏好 | 开关与目标语言存本机 `localStorage`（`myz-pdf-bilingual` / `myz-epub-bilingual`）；译文沿用 `myz_translate_db`，按 `源:目标:文本哈希` 命中，不同步、不出设备。开关持久化意味着重开阅读器时模式已开、没有点击：翻译引擎必须按请求现取，不能依赖启用动作初始化 |

**Rationale** 对照阅读的坐标系是原文，不是译文：块必须钉在源段落上，读者才能一眼对上；译文更长时只允许局部下推，分页/分章边界始终对齐。只译完整可见段落既省算力，也符合端上模型串行的现实；半可见段落留骨架而不是半截译文。

### 4.27 工作区骨架

工作区（文库、Inbox、素材、设置、查看器、快照）共用同一个壳。四个区各自有自己的责任，**页面只往区里放内容，不自己画壳**。

```
┌────┬──────────────┬──────────────────────────┬──────────────┐
│ 48 │ nav 240      │ header 48                │ panel 280    │
│rail│ (200–320)    │ ┌──────────────────────┐ │ (260–380)    │
│    │              │ │ 标题 · 计数 · 搜索   │ │              │
│ 图 │ 分组 1       │ ├──────────────────────┤ │ 详情 / 目录  │
│ 标 │   项 32      │ │ 批量条 44（按需）     │ │ / 大纲       │
│ 按 │   项 32      │ ├──────────────────────┤ │              │
│ 钮 │ 分组 2       │ │ 行 56 / 正文          │ │              │
│ 28 │   …          │ │        …             │ │              │
└────┴──────────────┴──────────────────────────┴──────────────┘
                    └ statusbar 28（仅后台任务时出现）┘
```

| 区 | 规格 | 规则 |
| -- | ---- | ---- |
| rail | `--myz-rail-w` 48 | 恒在、不折叠。图标 20、命中 32（`--myz-hit-compact`；rail 是一级导航，不用 28 的密集档），图标按钮之间 4。当前项：`--myz-surface-2` 底 + 左侧 2px `--myz-accent` 竖条。项数 3–6，超过 6 说明这个产品有两条主线，先解决导航结构 |
| nav | `--myz-nav-w` 240（200–320） | 分组之间 24、组内项之间 2；项高 32、左右 8；项右侧计数用 12 `--myz-muted`，选中项 `--myz-surface-2` + `--myz-accent-text`；可折叠为 0（rail 仍在），折叠状态记在本地 |
| main | ≥ 480 | 内部自己滚动，壳不滚动。列表吃满宽度，正文用 `.read-body` 38em 居中。**外层不再有 `max-width`** |
| panel | `--myz-panel-w` 280（260–380） | 默认收起；展开时挤压 main（不覆盖，换行更少比遮挡更可接受）；< 1200 改为覆盖抽屉 |
| header | `--myz-header-h` 48 | 吸顶，不随 main 滚动。左：标题 17/600 + 计数 12；右：搜索 32 + 视图切换 + 更多。底边 1px `--myz-line` |
| statusbar | `--myz-statusbar-h` 28 | 只在有后台任务（快照生成 / 同步 / 导入）时出现；一条任务一行，完成后 4s 淡出 |

**拖拽手柄**（nav 右缘、panel 左缘）：可见宽 4、命中宽 12，静止透明，悬停 `--myz-accent` 30%，拖拽中 100%。`role="separator"`、`aria-orientation="vertical"`、`aria-valuenow` 报当前宽度。键盘：聚焦后 `←/→` 调 8、`Home` 复位默认值、`Enter` 折叠/展开。双击手柄复位。拖到 clamp 边界后不再增长，**不换行、不改字号**。

宽度写本地设置（不同步，与 §3.6「设置只本地持久化」一致）。

**为什么要有 rail**：现在所有页面共用一条顶部通栏导航，切换要先把视线拉到顶边。rail 是常驻的「我在哪」，nav 是「这一区有什么」——两者分开之后，nav 可以随页面变（文库给来源，Inbox 给队列，设置给分组），rail 不变。

**不套这个骨架的面**：PDF / EPUB 阅读器（只用 rail + 右栏 240，见 §3.6）、采集条与所有浮层（§4.7/§4.8）、扩展弹窗（§4.21，360 系统面板）。

### 4.28 批量选择条

**什么时候出现**：选择数 > 0。为 0 时不渲染、不占高——不用「禁用态」占位。

| 属性 | 做法 |
| ---- | ---- |
| 位置 | main 顶部，header 正下方；吸顶，随 main 滚动时停在 header 下面 |
| 高 | 44；`--myz-surface-2` 底，底部 1px `--myz-line`，左右 `--myz-row-pad-x` |
| 内容 | 全选 checkbox + 「已选 3」12 + 动作按钮 28 + 右侧「取消选择」链接 |
| 顺序 | 正向动作（保留 / 归档 / 打标签）、分隔线、危险动作（删除）最右 |
| 危险动作 | 文字按钮 `--myz-error`，不实心红；执行后走 §4.30 的删除规则（即时消失 + 6s 撤销），不弹确认 |
| 选择行为 | Shift 连选、`Cmd/Ctrl+A` 全选**当前视图**、`Esc` 清空。选择态属于**当前视图**：切 tab / 切筛选 / 换搜索词即清空（现状 Inbox 就是这么做的，见 §4.25） |
| 触屏 | 常驻底部条（`--myz-hit-touch` 44），不放 top |
| 无障碍 | 条出现时 `role="status"` 播报「已选 3 条」；焦点不自动跳走 |

**为什么不做「确认弹窗」**：批量的风险是「一口气选错了 30 条」，只有撤销救得了；确认只挡得住「点错了一个按钮」，那个按钮点错，撤销一样退得回去。所以确认只留给 §4.30 轴一里的三类（带批注的记录、覆盖导入、清空缓存 / 清空历史），批量一律走撤销。

### 4.29 状态 pill

工作区里表示「这条现在处于什么状态」的唯一样式。**同一个状态在一行里只出现一次**：要么左侧 3px 色条，要么文字 pill，不叠、不加图标第三遍。

| 尺寸 | 高 / 字号 | 用在哪 |
| ---- | --------- | ------ |
| 行内 | 18 / 11 `tag` | 列表行的类型 chip、状态 pill |
| 面板 | 20 / 11 | 右栏表头、详情里 |
| 计数 | 16 / 11 | nav 项右侧数字，无边框 |

语义映射（颜色只从这四处取，不新增）：

| 语义 | 底 / 字 | 用于 |
| ---- | ------- | ---- |
| 进行中 | `--myz-info-bg` / `--myz-info` | 待处理、生成中、同步中 |
| 中性 | `--myz-surface-2` / `--myz-muted` | 稍后处理、已归档、已跳过 |
| 强调 | `--myz-tag-bg` / `--myz-tag-fg` | 类型标签（划线 / 摘录 / 收藏） |
| 危险 | `--myz-error-bg` / `--myz-error` | 失败、不可用 |

圆角 `--myz-r-sm`，左右内边距 6，无边框（计数 pill 例外：1px `--myz-line`）。

**为什么值得单独定**：同一个「待处理」现在有四种长相（`.settings__pill`、`.settings__list-status`、行内 `rounded-tag`、Inbox 的 `StatusPill`）。这不是审美问题——用户要靠 pill 的颜色判断状态，四种长相意味着颜色语义也在漂。

### 4.30 删除与撤销

破坏性动作只有两条轴，不按「这是哪个面」判断。

**轴一：能不能重建 → 决定要不要确认**

| 后果 | 守卫 | 例子 |
| ---- | ---- | ---- |
| 能重建（记录本身、缓存项、阅读历史、Inbox 状态） | **不确认，即时消失 + 6 秒撤销** | 删除一条无批注的划线、移出一条历史、批量删除 |
| 记录里住着用户写的东西，删了页面重做不出来（带批注的记录） | **确认，且不提供撤销** | 删除一条带批注的划线 |
| 不能重建（覆盖、清空、跨对象重写） | **确认，且不提供撤销** | 覆盖导入、清空缓存区、清空阅读历史 |

**批注为什么单独一行**：一条划线删了，回原文再划一次就有了——这是「能重建」。但批注是用户自己敲的一段话，页面上没有原文可依据，删掉就是没了。所以「带批注」不是「能重建」的一个变体，它是判据的另一侧。

这条判断只看**被删的东西里有没有用户写的字**，不看它在哪个面。所以带批注的划线在内容层、文库、Inbox、查看器里都是同一个处置，只是确认框出现在触发点旁边（§4.18）。

**确认与撤销不叠加**：带批注的记录有确认就不给撤销。两个守卫挡的不是同一件事——确认挡「点错了」，撤销挡「选错了 / 后悔了」。单条删除只可能「点错」，没有「选错」，所以确认够用；再叠一个撤销等于每次删带批注的记录都拦两次，而 §4.28 的批量条已经用撤销覆盖了「选错」那一类。

**批量里混着带批注的记录，仍走撤销，不逐条确认**：一次选中 12 条里有 3 条带批注，逐条弹 3 次框只会让人闭眼点确定，守卫等于没有；而用户真正需要的是「知道刚才删掉了什么、还能退回去」。所以整批即时删除 + 撤销，**代价写进撤销文案**：「已删除 12 条（含 3 条带批注）· 撤销」。信息给了，守卫不叠。只有「单条 × 带批注」才弹确认。

**优先级一句话**：单条带批注 → 确认；批量（不论是否含带批注）→ 撤销；单条无批注 → 撤销；清空 / 覆盖 → 确认。

**轴二：作用范围 → 决定撤销挂在哪儿**（只对「有撤销」的删除有效；有确认的那两类不看这张表）

| 范围 | 撤销位置 |
| ---- | -------- |
| 浮层与阅读器（批注浮层、采集条、PDF / EPUB 的 Inspector、弹窗） | 右上提示条（形态、时长、堆叠见 §4.15；6 秒，带一个文字动作「撤销」） |
| 页面内的列表与工作区面板（文库、Inbox 的列表与右栏、素材、阅读历史） | 本区内上方的行内条（`role="status"`），不遮内容 |
| 批量（N > 1） | 同一个行内条，撤销整批而不是逐条；文案要把代价说出来：「已删除 12 条（含 3 条带批注）· 撤销」，没有带批注的就省略括号 |

**动词表**（一个动作一个词，§2.7）

| 实际发生的事 | 用 | 不要用 |
| ------------ | -- | ------ |
| 记录真的没了 | 删除 | 移除、清理 |
| 只是从本地列表里不显示（文件和高亮都还在） | 移出列表 | 删除 |
| 把一组全清掉 | 清空 | 删除全部、批量删除（作按钮文案时用「清空历史」） |
| 用新数据盖掉旧的 | 覆盖导入 | 导入 |

**批量因此也不弹确认**：批量删除的风险是「一口气选错了 30 条」，只有撤销救得了；确认只能挡住「点错了一个按钮」，而那个按钮点错，撤销一样退得回去。所以 §4.28 的批量条只有撤销。

**为什么 6 秒**：和 §4.15 的提示条时长同一个值，不另设参数。撤销窗口内不写存储（延迟提交），所以撤销恢复的是「从没被改过的记录」，不是反向补写。

**宿主销毁时必须提交，不是取消**

延迟提交只在「宿主还活着」的前提下成立。组件卸载（`dispose`）、页面关闭、切走标签页、扩展被卸载时，**立即把待决删除写进存储，默认视为用户已确认**。

理由是不对称：「用户看到已删除、其实没删」的后果是记录下次刷新全回来、批量删除直接失效、每次删除都要重来一遍；而「撤销条没来得及点」只是少救一次，而 6 秒内不点本身就是默认接受。所以销毁路径上的默认动作只能是提交。

两条实现约束：提交必须**幂等**（同一个 id 重复提交不报错——销毁路径可能与定时器竞争，两边都可能触发）；销毁路径不许「清掉定时器就返回」，那等于把删除丢掉。

**验收**：在 6 秒窗口内强制关闭页面 / 切走标签，重开后该记录确实已删除（批量删除同理，整批都在）。这条比「撤销能恢复」更该先测——撤销失败只是少一个功能，销毁丢写会让删除功能本身不可信。

备选（不采用）：把待决删除持久化，下次启动恢复撤销条。它多一套状态机和过期清理任务，与 0.7「稳定优先」冲突。

**验收**（0.7 落地时必须能跑）：`grep -rn "window.confirm" myz-annotator/src packages` 业务调用 0 处；12 个破坏性调用点各自落到上面两条轴的正确格子；「移出列表」与「删除」在文案上分开。

## 5. 内容与文案

**基调**：短、能做、说人话。空状态是说明，不是报错。

| 说的是什么       | 就这样写       | 不要写               | 原因                     |
| ---------------- | -------------- | -------------------- | ------------------------ |
| 产品名           | MyZ            | 通用智能助理         | MyZ 聚焦采集与回看；Inbox 的本地线索不是聊天助手 |
| 给选区上色       | 划线           | 高亮、划线标注       | "高亮"是样式名，容易混   |
| 只保存文字       | 摘录           | 保存文字、文字       | 与划线并列的一种记录     |
| 自己写的那句     | 批注           | 笔记、评论           | "评论"听着像社交软件     |
| 同一个网页的汇总 | 来源           | 网页书签             | 网页和 PDF 都用这个词    |
| 回到原本的位置   | 打开原文       | 定位、查看           | 用户知道点下去会发生什么 |
| 按文中位置排序   | 文中顺序       | Range                | 是代码里的字段名         |
| 只看网页正文     | 专注阅读       | 禅定模式             | "禅定"只留给代码         |
| 一条都没找到     | 这里还没有记录 | 没有符合条件的记录。 | 说清楚情况，不写客套话   |
| 记录类型筛选     | 摘录           | 文字                 | 与"只保存文字"同一个词   |
| 列表里没有批注   | 还没有批注     | 无批注、暂无批注     | 空状态是说明，不是标签   |
| 列表里没有标签   | 还没有标签     | 无标签               | 同上                     |
| 记录正文为空     | 这里还没有内容 | 无可展示内容         | 说清楚现状               |
| 同步协议版本     | 同步版本       | Manifest 版本        | 不暴露内部字段名         |
| 打开 PDF         | 在阅读器中打开 | 定位、查看           | 与"打开原文"区分动作     |
| 新内容处理入口   | Inbox          | 待办箱、知识中枢     | Inbox 是采集处理队列，不是第二文库 |
| 保留内容         | 保留入文库     | 完成、保存一下       | 明确表示记录进入文库常规视图 |
| 隐藏但不删除     | 归档           | 丢弃、删除           | 记录仍可在文库归档筛选、搜索和导出中找到 |
| 自动关键词       | 关键词         | 标签、主题           | 关键词是本地线索，不写入用户标签 |
| 自动原文摘取     | 代表句         | AI 摘要、结论        | 代表句直接来自原文，不改写事实 |
