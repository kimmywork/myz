## 必须改

1. **`showcase.html:430` 的「行高 ≈ 165」与实测不符，`:420/:426/:437` 的「同样 480 高」也不成立。**
   实测：旧行 151px（3 行）、旧容器 480px、新容器 **448px**（不是 480）、新行 56px×8。`oldVisible=2`、`newVisible=8` 这两个结论数字成立，但对照组容器高度差 32px，且 165 是错的。
   影响：这是整页唯一「能看出丑变好看」的论据，数字错一个就会被人说「对比做了手脚」。
   改法：两个 viewport 统一 480，或把标题改成「480 vs 448」；`行高 ≈ 165` 改成实测 151（或把旧行样式调到真 165）。

2. **规范对「导航项」的高度自相矛盾：28 vs 32。**
   `design-system.md:101`（§2.5 紧凑档：控件 28，用途写「导航项」）和 `:174`（`--myz-hit-dense` 说明「导航项」）说导航项用 28；`:445`（§3.5 工作区字号表）和 `:1221`（§4.27 nav 项高 32）说 32。Designer 这轮只统一了 rail（改成 32），nav 项这处漏了。
   影响：实现侧照 §2.5 会做出 28 高的导航项，照 §4.27 会做 32，两边都能引用规范。
   改法：按 rail 的理由统一成 32，并把 §2.5/:174 里「导航项」字样移到 32 档（`--myz-hit-compact`）。

3. **`design-system.md:1247` 的交叉引用指错了节。** §4.28 批量条写「执行后走 §2.7 的删除规则」，但 `:1255` 附近的 §2.7 是「一个动作一个词」，不是删除规则。
   影响：实现者按引用跳过去会找不到规则，最后各写各的。
   改法：指向真正写删除处置的地方（建议在 §4.15 或 §4.28 内补一段「删除 = 即时消失 + 6s 撤销，确认只留给不可重建动作」，再引用它）。

4. **卡片自相矛盾：决定 2 说卡片只留给空态/设置分组/快照正文，场景表却保留「卡片瀑布流」视图。**
   `:1396`（决定 2）排除了列表卡片；但 `:1317`（§6 文库）写「flush 行 56 / 卡片瀑布流两视图」，§4.9 的卡片瀑布流整节还在。
   影响：0.7 到底删不删瀑布流视图，规范和场景表给了两个答案；实现时「卡片」的边界不清。
   改法：二选一并写清——保留瀑布流就在决定 2 加例外；砍掉就改 §6 与 §4.9。

5. **showcase 的两个拖拽手柄没有 `aria-valuenow`，与它自己演示的规范冲突。**
   规范 `:485` 和 `:1227` 明确要求 `role="separator"` + `aria-valuenow` 报当前宽度；实测两个手柄 `aria-valuenow/min/max` 全为 `null`（只有可见的 `header__readout` 文本）。
   影响：键盘用户听不到当前宽度；showcase 作为规范的可执行样张，把一条无障碍要求漏掉了。
   改法：在 `updateReadout()` 里同步写 `aria-valuenow`（`aria-valuemin`/`max` 写 200/320 与 260/380）。
