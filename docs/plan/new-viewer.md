# myz-annotator 全新的查看器

Dashboard 页面可以直接以列表或者卡片的形式展示所有的标注内容，当点击“查看”链接时会打开一个modal展示标注详情。这种情况下展示的信息非常有限，而且无法查看相关联的结果。同时如果是长篇内容（比如直接保存下来的长文或者AI生成的Markdown），在Modal中显示很不友好，也无法沉浸式阅读和查看。

新的查看器我希望设计成下面的样子：

通过 /highights/:id 的路由访问一个新的页面，展示标注详情。这个页面的设计可以参考一些在线文档或者笔记工具，比如 Notion、Evernote 等，提供一个干净、简洁的界面来展示标注内容，同时同一个页面上的多个标注，可以明显能够在前后看到（视觉呈现上略有差异，以作区分），并且可以点击切换过去。查看区域可以滚动，并且滚动到底部自动切换到当前页面的下一个标注，（如果当前页面已经没有可以加载的标注，则切换到下一个与当前标注挨着的页面）。查看器中，某个特定页面标注的排列顺序可以根据添加时间，也可以像是拓扑排序一样，按照标注的Range顺序来排列 - 这个由用户选择。

除了滚动到底切换到下一个标注以外，还可以通过左右两边的箭头导航到时间上相邻的不同页面上的标注。

因此在这一概念上，就出现了一个网页的概念。我们之前加入了一个新的record kind - bookmark，就是为了对这部分的标注进行聚合。另外对于有内容的标注比如highlight和clip，按照产生的方式分别给他们的内容添加响应的content-type。比如保存自Chat页面的就是text/markdown（也就是带有AI-generated标签的），而直接从网页保存过来的就是 text/html。用户的note则默认是text/markdown。

因此查看器里显示的内容要根据这么一个content-type来决定如何渲染。

同样，因为有了页面的概念，在Dashboard的highlights页面加入第三种布局，这种布局时双栏式，左侧是按照时间排序最近添加的网页列表，右侧是当前选中网页的标注内容。用户可以通过点击左侧的网页来切换右侧展示的内容。右侧展示的内容同样可以按照添加时间或者Range顺序来排列。这个布局并不与Card/List的展示冲突，而是作为一个可以折叠/展开的sidebar来呈现。展开以后，就可以通过网页来筛选cards/lists。
