> 状态：**设计已确认，待实现**（2026-10-08）。
>
> 关联：
> - 安全/密钥模型：`docs/plan/e2ee-security-hardening.md`（KM1–KM5、roster、D、按设备签名）。

## 1. 目标
把「加密同步」从“给已配置设备用的设置页”改为**面向首次配置的向导**：引导用户选择场景（加入 / 新建 / 授权新设备）、逐步填写并校验参数（含 S3）、并在每一步提示“在另一台设备上该怎么做”。配对保持**文本复制粘贴**（不引入 QR 库）。

## 2. 已锁定决策（2026-10-08）
1. **载体**：独立全屏路由 `#/setup`；**首次进入「加密同步」且本机无账号时自动弹出**（一次性，用本地标记 `syncSetupSeen`）。
2. **邀请串携带非敏感 S3 参数**（endpoint/region/bucket/prefix）用于新设备预填；`accessKeyId/secretAccessKey/sessionToken` **不随串传递**，由用户手填。
3. **不做导出备份**（无 A-only 恢复的风险以文案强提示，不提供导出入口）。
4. **迁移步骤始终显示**；向导**必须完成一次同步**（v2 上传成功）才允许结束（失败可重试，不可跳过）。
5. 配对/迁移一律**复制粘贴文本**。
6. 设置页的「设备配对」整块**移除**，改由向导入口承担“生成邀请 / 批准”。

## 3. 角色与总流程
```text
#/setup
 └─ Step 0 选择场景
     ├─ (A) 加入已有账号        （新设备）
     ├─ (B) 新建账号            （首台设备）
     └─ (C) 给新设备授权        （已有设备；取代原「设备配对」）
```
- 本机**已有账号** → 仅 (C) 可用；(A)/(B) 置灰并提示“本机已配置”。
- 本机**无账号** → (A)/(B) 可用；(C) 置灰（“请先在已有设备上创建账号”）。

## 4. 分步设计（含线框、校验、跨设备提示）

### 分支 B — 新建账号（首台设备）
**B1. S3 配置**（有则预填 `readSettings().sync.s3`）
```text
┌ 设置同步 · 1/5  S3 存储 ───────────────────────┐
│ Endpoint*      [ https://s3.example.com      ] │
│ Region         [ us-east-1                   ] │
│ Bucket*        [ myz-sync                    ] │
│ Access Key ID* [ ************               ] │
│ Secret Key*    [ ••••••••••••••             ] │
│ Session Token  [ 可选：S3 临时凭证(STS)需要   ] │
│ Prefix         [ 可选                        ] │
│ ⚠ 非 https 仅允许 localhost/127.0.0.1         │
│ [ 测试连接 ]   ✓ 成功 / ✗ 失败原因             │
│                          [ 上一步 ] [ 下一步 ]│  ← 测试通过才可下一步
└───────────────────────────────────────────────┘
```
- 校验：必填非空；endpoint 必须 `https://` 或 loopback；`测试连接` = `S3Client.listObjects(prefix)`。

**B2. 迁移旧数据**（始终显示；`bootstrapV2Account({rescue:true})`）
```text
┌ 设置同步 · 2/5  迁移旧数据 ────────────────────┐
│ 若你以前用旧格式同步过，这里会把旧云端记录一次性 │
│ 合并到新账号，然后清理旧密钥。                  │
│ 旧同步密钥 [ ••••••••• ]                        │
│ ▸ 旧 S3 与上面不同？[展开单独填写]              │
│ [ 迁移 ]  （未检测到旧数据 → 显示“无需迁移”）   │
│ ⚠ 迁移失败可重试；不提供跳过。                  │
└───────────────────────────────────────────────┘
```
- 校验：`deriveKeysetFromSecret` 得到旧 keyset；`pullLegacyRemote` 读旧远端版本；失败给明确原因。
- 无旧数据时：仍显示本步，文案“未检测到旧格式数据”，直接继续（**非跳过**语义，视为完成）。

**B3. 创建账号**
```text
┌ 设置同步 · 3/5  创建账号 ──────────────────────┐
│ [ 创建同步账号 ]  (进行中…)                     │
│ Account ID  acct_xxxxxxxx   [复制]             │
│ ⚠ 无 A-only 恢复：设备全丢=数据不可恢复。        │
└───────────────────────────────────────────────┘
```

**B4. 首次同步（强制完成）**
```text
┌ 设置同步 · 4/5  首次同步 ──────────────────────┐
│ 正在上传本机数据…  [进度/状态]                  │
│ ✓ 同步完成（N 条）；✗ 失败 → [重试]（不可跳过） │
└───────────────────────────────────────────────┘
```

**B5. 完成 + 引导加设备**
```text
┌ 设置同步 · 5/5  完成 ──────────────────────────┐
│ ✓ 账号已建立并同步                             │
│ [ 添加新设备 ]（→ 分支 C）   [ 完成 ]           │
└───────────────────────────────────────────────┘
```

### 分支 A — 加入已有账号（新设备）
**A1. S3 配置**（默认空白；**若邀请串含非敏感参数则预填**）— 同 B1 的校验。

**A2. 获取邀请**
```text
┌ 设置同步 · 2/5  获取邀请 ──────────────────────┐
│ 请在【已有设备】上：设置 → 加密同步 → 添加新设备 │
│ → 生成配对邀请，然后把邀请串发给我。            │
│ 邀请串 [ 粘贴邀请串 ……………………………… ]          │
│ ✗ 无效或已过期（有效期 10 分钟）                │
│                          [ 上一步 ] [ 下一步 ] │
└───────────────────────────────────────────────┘
```

**A3. 生成响应 + 短码**
```text
┌ 设置同步 · 3/5  核对短码 ──────────────────────┐
│ 本机短码： 4 8 2 9 1 7                          │
│ 把【响应串】发回已有设备：                       │
│ [ 响应串 ……………………………… ] [复制]               │
│ 已有设备会显示它的短码；两边必须一致。            │
└───────────────────────────────────────────────┘
```

**A4. 导入配对串**
```text
┌ 设置同步 · 4/5  完成加入 ──────────────────────┐
│ 已有设备批准后给你一串【配对串】。               │
│ 配对串 [ 粘贴配对串 ……………………………… ]          │
│ ☐ 我已确认：已有设备短码与本机一致(482917)      │  ← 必须勾选
│ ✗ 尚未被批准 / 配对串无效                        │
└───────────────────────────────────────────────┘
```
- 校验：验 roster 签名 + 解封 D（本设备是否被授权）；未勾选 SAS 不可完成。

**A5. 首次同步（强制完成）** + 完成页。

### 分支 C — 给新设备授权（已有设备）
**C1. S3 配置**（未配置才显示；已配置则跳过）。

**C2. 生成邀请**
```text
┌ 添加新设备 · 1/3  生成邀请 ────────────────────┐
│ [ 生成配对邀请 ]                                │
│ 邀请串 [ ……………………………… ] [复制]               │
│ 发到新设备，让它在向导选「加入已有账号」粘贴。   │
└───────────────────────────────────────────────┘
```

**C3. 粘贴响应**
```text
┌ 添加新设备 · 2/3  新设备响应 ──────────────────┐
│ 新设备短码： 4 8 2 9 1 7                        │
│ 响应串 [ 粘贴响应串 ……………………………… ]          │
└───────────────────────────────────────────────┘
```

**C4. 核对并批准**
```text
┌ 添加新设备 · 3/3  核对并批准 ──────────────────┐
│ 本机短码： 4 8 2 9 1 7                          │
│ ☐ 我已确认与新设备短码一致(482917)              │  ← 必须勾选
│ [ 批准并加入设备 ]                              │
│ 批准后把【配对串】发回新设备：                   │
│ 配对串 [ ……………………………… ] [复制]               │
│ ✓ 设备已加入（Device ID / Epoch）               │
└───────────────────────────────────────────────┘
```

## 5. 邀请串载荷扩展（schema-first）
- `packages/sync-core/src/pairing.ts` 的 `PairingOffer` 增加可选字段：
  ```ts
  interface PairingOffer {
    accountId: string
    hostDeviceId: string
    ephPub: string
    nonce: string
    s3?: { endpoint: string; region: string; bucket: string; prefix?: string }  // 非敏感
  }
  ```
- `myz-annotator/src/background/sync/v2/pairingSession.ts`：`createPairingInvite` 读取 `settings.sync.s3` 填入 `s3`（**仅非敏感项**）；`acceptPairingInvite` 返回时把该 `s3` 交给 UI 预填。
- 敏感项（accessKeyId/secretAccessKey/sessionToken）**永不入串**。

## 6. 首次弹出与入口
- 新增本地设置 `syncSetupSeen?: boolean`（`myz-annotator/src/background/settings.ts` + schema/normalize）。
- 进入 `#/settings/sync` 时：`!hasAccount && !syncSetupSeen` → 跳转 `#/setup`（`SyncSection` 的 `onMounted` 里 `router.replace("/setup")`，或在路由守卫）。
- `#/setup` 首次展示时置 `syncSetupSeen=true`（或“稍后”时置），保证只弹一次。
- 设置页保留「设置同步」按钮作为再次进入向导的入口。

## 7. 设置页改造（已配置设备）
- **删除「设备配对」整块**（现 `SyncSection.tsx` 的三步配对 UI）。
- 顶部状态卡：Account ID / Device ID / Epoch / 上次同步。
- 动作：**立即同步**、**添加设备**（→ `#/setup` 分支 C）、**解除账号**、**高级设置**（S3 配置编辑；账号存在时旧格式密钥/KeyId 继续隐藏，见 `881ccd3`）。
- 无账号时：主按钮 **「设置同步」**（→ `#/setup`）。

## 8. 迁移与强制初始同步
- 迁移（B2）始终显示；`bootstrapV2Account({ rescue: true })` 内：`pullLegacyRemote` → `applyRecordPayload` → 建账号 → `syncAccountNow` → 清理旧 keyset。
- **强制同步完成**：向导在 B4/A5 调用 `myz:syncNow`（v2），`ok===true` 才允许“完成”；失败只提供“重试”（不可跳过）。
- 无旧数据时迁移为显式“无需迁移”状态，仍计为完成。

## 9. 边界与错误
| 情况 | 处理 |
| --- | --- |
| S3 校验失败 | 本步阻塞，显示原因，可重试 |
| 邀请过期（10 分钟） | 提示在主机重新生成 |
| 邀请/响应/配对串格式错 | 解码失败给明确错误 |
| SAS 不一致 | 硬停止并警告（疑似中间人），不可继续 |
| 配对串无效/未批准 | “请确认主机已批准后重试” |
| 本机已有账号 | A/B 置灰 |
| 迁移失败 | 可重试；不提供跳过 |
| 首次同步失败 | 可重试；不提供跳过 |

## 10. 实现增量

- **I1（向导壳 + 路由 + 首次弹出）**：`#/setup` 路由、Step 0、`SyncSection` 移除配对块 + 入口 + 首次跳转。

- **I6（e2e）**：扩展 `tests/extension/sync-mock-s3.spec.ts`——用 mock S3 跑 B（新建+迁移+强制同步）与 A/C（跨 profile 配对）的向导路径；断言各步校验与 SAS 门禁。

## 11. 验收标准
- 首次进入加密同步自动进入向导；再次进入不自动弹。
- 三个分支均可在向导内完成，且每步有校验或跨设备提示。
- 邀请串带非敏感 S3 参数并可预填；敏感项不出现于串中。
- 迁移步骤始终出现；向导在初始同步成功前无法结束。
- 设置页不再有独立「设备配对」块；仅保留状态 + 动作 + 高级。

## 12. 未决/风险
- 邀请串长度（含 S3 参数）可能较长；粘贴体验与文本域高度需实测。
- 同一 S3 但不同 prefix 的误配 → 迁移/同步会失败，向导需明确报错。
- 强制同步在大库时耗时；需要进度反馈与可取消（取消后不得视为完成）。
- 无 QR：跨设备需人工复制多段串；文案需足够清晰。
