# 0.7.0 版本计划：工作区收口 + 整页快照

> 状态：**规划中**（2026-11-10 用户拍板范围，未开工）。
> 当前版本 `0.6.7`（未发布）；用户侧实际普遍在 `0.6.6`。

## 1. 为什么不再叫 1.0

2026-11-10 用户决定：**不设「1.0 正式版」这个里程碑**，改为继续迭代，下一个目标版本 `0.7.0`。

依据：

- 1.0 隐含「稳定承诺 + 不可逆迁移」，而同步目前是试验性功能（不承诺可恢复），用户群已在 `0.6.6`——两个前提都不成立。
- 仓库里没有任何「1.0 承诺什么」的定义；没有定义时「还差哪些事」只能退化成愿望清单。换成一个具体版本号，范围反而切得动。

## 2. 判定原则

一句话：**不做它，现有用户的现有数据或现有动作是否已经受损。** 是 → 进 `0.7.0`；否 → `0.8` 或更后。

用户补充的三条前提：

- 同步是试验性功能，**不承诺可恢复**。这条要落到用户可见处（见 §6-5），不能只留在文档里。
- 附件暂不同步，本地-only。
- 选择态属于**视图**，不属于对象：切换视图（tab / 筛选 / 搜索）即清空。

## 3. 范围

### 3.1 整体设计修订（Designer 主导，本版最大件）

现状：Dashboard、阅读器、Inbox、Popup 四处的样式没有完全遵循设计系统；设计系统之上也没有统一组件层，而是工具类、`.btn`、`.settings__*`、`dashboard-ui` 四层并存。用户判断：**dashboard 很丑**。

目标形态（用户给的三个参考）：

- ChatGPT 式：左侧固定导航 + 中央宽工作区 + 顶部状态；
- Gmail 式：导航 / 列表 / 阅读三栏，行高紧凑，右侧为当前项详情；
- Craftatory Engine 式：图标栏 + 文件树 + 主区 + 右侧 outline / backlinks 面板。

共同点即验收口径：**紧凑、上下文信息密度高、多栏布局承担导航与状态指示、边栏可调整以动态改变工作区视口。**

做（用户 2026-11-10 明确：不是把现有样式收敛，而是 revise 一遍整体设计——设计系统本身 + 每个页面的具体元素与样式）：

- **设计系统本身**：token 增删与语义修正（不换配色方案）、组件规格（`Button` / `Dialog` / `SelectionBar` / 面板 / 输入 / 菜单）、密度基线（行高、间距、字号档位）、场景表补全（含「页面快照」「素材」两个新面），以及规范里没写清的「撤销提示落位」。
- **每个页面的元素与样式**：逐页给布局骨架、元素清单、密度、状态（空态 / 加载 / 错误 / 选中 / 禁用）、断点行为。覆盖面 = 用户能进入的全部界面：dashboard 各页、PDF/EPUB 阅读器、popup、内容浮层、stitch（同时给去留建议）。
- **组件层**：API 形态照 shadcn（组件 + `variant` / `size`），变量仍用 `--myz-*`，不引 React、不迁 shadcn 词表。
- **布局壳**：可折叠 / 可调宽边栏 + 三栏骨架，各面共用一套原语；popup 只取所需子集；内容脚本保持手写，取值同源。
- 把 drift check 扩到实现层（禁止裸 hex 色值），否则这轮修订会再漂回去。

交付物（缺一件不算完）：

1. 修订后的 `docs/research/design-system/design-system.md`（或逐条 patch，标明改了哪节、为什么）。
2. 逐页规格：每页一节，元素 / 布局 / 密度 / 状态清单，能与实现逐条比对。
3. 迁移清单：哪一层先动、每步的验收看用户可见的变化，而不是「换了组件」。

节奏：先出方向稿（密度基线、三栏骨架、token 与组件差异清单、一个页面的完整样例），用户确认后再铺其余页面。

不做：

- 配色方案重做、shadcn-vue 全量迁移。
- 信息架构与路由重排（除非布局确实要求）。
- 内容脚本注入页面的样式体系（保持手写，仅取值同源）。

### 3.2 删除语义统一

规则有**两条轴**，不是一条：

1. **能不能重建**——决定要不要确认框。
2. **作用范围**——决定撤销条有没有地方挂。

- 单条或选中的若干条（记录**不带批注**、缓存项、阅读历史里的单条）→ 即时消失 + 6 秒撤销，不弹确认。
- 记录里住着用户写的东西（**带批注**）→ 确认，且不给撤销：批注是用户敲的，页面里重做不出来，属「不能重建」那侧。
- 批量里混着带批注的记录 → 仍走撤销、不逐条确认（重复确认会退化成闭眼点确定），撤销文案里写明「已删除 N 条（含 M 条带批注）· 撤销」。
- 整列表清空（清空阅读历史、清空缓存区）、覆盖导入 → `ConfirmPopover` 确认，不提供撤销。
  理由：撤销条依附在「列表」上，列表清空后它无处安放；且一次恢复几百条的成本与失败风险，远高于弹一次框。
- 「从列表移除单条」与「清空历史」是**两个动作**（不同动词、不同处置），不共用文案。

现状：11 处走原生确认、跨三条代码路径；阅读页、查看器、缓存区三处**没有删除入口**。

做：

- 把内容层已有的 6 秒撤销（`content/highlight/pending-delete.ts`）提成共享能力。
- 文库与 Inbox 的单条、批量改为即时 + 撤销（现有文案「删除后不可撤销」删除）。
- 阅读页只做「从列表移除」（不删文件、不删高亮），动词与该语义对齐。
- 查看器补删除，复用 `dashboard-ui` 的 `HighlightActions`，不新写按钮。
- 原生确认只允许存在于 `@myz/shared/dialogs` 一处封装内。

验收：业务调用点原生确认 **0 处**；每个删除动作要么有撤销、要么有确认，二者不并存。

### 3.3 批量操作

只做三个面：

- **文库**（P1）：批量删除、批量打标签、批量导出。这是唯一「几百上千条」的面。
- **缓存区**：批量删除、批量「存为记录」（一次截十张不必逐张点）。
- **阅读页**：只给「清空历史」（条目量级小，不需要选择态）。

形态照 Inbox 现有实现（行首 checkbox + 顶部操作条 + `已选 N`），不发明第二套。
查看器不给批量——它是单条浏览，加选择态会把「上一条 / 下一条」的浏览语义弄浑。

选择态属于视图：切 tab / 切筛选 / 换搜索即清空；同一视图内翻页与滚动加载保留。

### 3.4 整页快照视图

> 命名（2026-11-10）：用户可见名用**「快照」**。它只承诺「某一时刻的复制」，不暗示永久，正好和「空间不足会清最旧」相容；代号同 Zotero 的 Snapshot 与搜索结果的「网页快照」。代码与文档内部同名。

形态：**只读、静态、带高亮锚点的页面快照**。不是登录态重放，不可交互。它是查看器的第二个视图（≥900px 时右侧保留记录列），不新增页面壳与导航项。

存储粒度：**按页面存**（用户拍板）。同一 URL 多份快照 = 版本列表，默认展示最新，不自动合并。

存储预算与淘汰（缺这条就是「配额写满后静默失败」）：

- 快照单独 store，**不混进 `staged_assets`**（后者单条上限 64MB 且没有淘汰策略）。
- 设总量上限；超限按 **LRU** 淘汰最旧的快照。上限默认值待定：先量一份典型快照的体积，再定数字（§6-2 探针一并做）。
- 写入失败（配额、序列化）必须**冒泡到 UI**，不能静默；淘汰发生前给用户一次提示。
- 验收：把存储配额逼到上限，确认写入失败可见、淘汰按 LRU 生效、不产生半截快照。

管理权（2026-11-10）：**不给用户管理界面**——不做占用管理页、不做手动保留/删除、不做快照列表管理。这是有意的取舍：快照空间不足时最旧的仍会被清理，所以必须留一行**只读状态**（「本机快照 · 占用 X MB · 空间不足时最旧的会被清理」）来兑现诚实；这行不是管理权，用户改不了任何东西。

内容边界：复用专注阅读的正文边界（`content-extraction.ts` 的 `findPrimaryContentElement` + `zen-config.ts` 的站点规则），保证「当时看到的」与「回看时的」是同一份边界。

截断规则（用户拍板）：无限滚动页面**不做整页快照**。以 record 为锚向两侧扩展，连续 N 个元素都没有命中相邻 record 时停止。N 待探（§6-2）。

锚点降级顺序：快照内 `SerializedRange` → 文本引用（`serializer` 的 `findRangeByNormalizedText`）→ 「未定位」。**绝不猜位置。**

兜底：快照不可变；顶部状态条显示「快照 YYYY-MM-DD · 原页可能已更新」+「打开原页」；不做自动差异比对。

验收：同页 20 条记录 + 1 份快照，给出锚点命中 / 降级 / 未定位的基线数字；普通文章、SPA 列表流、长评论流三类站点各验一次截断规则。

### 3.5 素材页

现状：所有采集只进图片缓存区并同时下载一份到磁盘；缓存区只能从 popup → 拼图编辑器进入，dashboard 里没有素材页。存了图找不到，比任何视觉问题都伤。

做：dashboard 增加「素材」页，与「阅读」并列；缓存项可预览、可删除（支持批量）、可「存为记录」（见 §3.6）。

### 3.6 图片 / 视频存为记录（窄）

- 缓存项 →「存为记录」：`kind = clip` + 附件引用，**附件本地-only、不参与同步**。
- context 默认带三项、不给关：来源页 URL + 标题、文字上下文（有选区取选区，否则取最近文本块前后各约 200 字）、视频时间戳 `mm:ss`（深链 `?t=` 可跳回）。
- 批注可选、默认收起（采集要轻，先存后注）。
- 回看：记录卡 16:10 缩略 + 类型角标；视频帧角标显示时间。
- 导出：本版导出**不含附件**，但导出结果里必须写明「N 个附件未包含（仅本机）」并给出清单；禁止出现「看起来完整、实际残缺」的备份。附件打包导出留到下一版。
- 批量「存为记录」：做（用户拍板 2026-11-10）。一批选中后一次落库，context 取公共部分（来源页、时间），缺失的留空，不逐张补。
- 不做：附件同步、换设备后附件恢复（显示「图片在本机」占位）。

### 3.7 本版不做

- **国际化**：推到 `0.8`。用户定：先做 UI 样式 / 设计系统，`0.8` 再上国际化。
- **知识化**（聚合分析 / 知识发现 / 缺口提醒）：1.x。前置是「什么叫分析得有用」的验收标准，先做探针。
- **多端**（阅读器独立端、桌面全局取词）：1.x，3 个月量级；便宜的替代（剪贴板 + 悬浮条，1–1.5 周）可作为先行验证。
- 视频字幕抓取（第三方接口不稳定、有合规成本）。
- shadcn 全量迁移、颜色方案重做。

## 4. 验收（整版）

1. 关键路径 e2e 清单全绿：采集 / 高亮 / 删除撤销 / 批量 / 快照回看 / 导入导出 / PDF + EPUB 重开还原。
2. 关掉 CI retry 连跑 10 次全绿，取基线（现在 retry 会吞掉 flaky，「CI 绿」不算证据）。
3. 删除：业务调用点原生确认 0 处；每个删除动作撤销与确认不并存。
4. 快照：锚点命中率有基线数字；三类站点截断规则生效。
5. `dist` 体积上限。
6. 设计系统：实现层无裸 hex 色值（drift check 覆盖实现）。

## 5. 切片建议（顺序待排期确认）

- **S1 整体设计修订**：先出方向稿（密度基线 / 三栏骨架 / token 与组件差异 / 一个页面完整样例），用户确认后再铺逐页规格；实现侧先从 `Button` + `Dialog` + 布局壳落 2–3 个页面看效果。
- **S2 删除统一 + 批量**。
- **S3 素材页 + 存为记录**。
- **S4 整页快照**：采集 → 存储 → 回看三段。
- **S5 密度与状态指示打磨 + 关键路径 e2e 补齐**。

S1 与 S2 可并行（S2 不依赖新组件即可开工，但最终要换到新 `Dialog`）。

## 6. 未决与探针

1. **快照的页面身份**：同一 URL 改版前后算不算同一页？决定记录要不要加 `domVersion`、决定快照是「记录的容器」还是「独立文档库」。探法：两个改版前后的真实页面 + 同一条划线走定位，1–2 天。
2. **截断阈值 N**：在真实无限滚动页面（X/Twitter 首页、长评论流）上量，半天到 1 天。
3. **选择态行为表**：切 tab / 切筛选 / 搜索 / 翻页 / 滚动加载 五种操作 × 保留或清空，半天。
4. **0.7.0 的 UI 密度基线**：以哪张参考图为基准（三张图各自的密度不同），由 Designer 定。
5. **同步试验性的用户可见文案**：写在哪（设置页 / 首次连接 / release notes）、用什么措辞。
