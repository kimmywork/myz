## 2026-11-03T19:40:00+08:00

CI 改为 master 触发，并新增 master 的 nightly 预发布。

- `.github/workflows/extension-ci.yml`：`push.branches` 由 `main` 改为 `master`（仍按 `myz-annotator/**`、`packages/**`、workflow 自身做路径过滤）；`pull_request` 不变。
- 新增 `pre-release` job（`needs: build-and-test`，`if: push && refs/heads/master`）：下载构建产物 → 用 `myz-annotator/package.json` 的版本 + 最近合并 PR 的合并日期/编号生成版本号（例：`0.6.6.20261103-105`）→ 改写 `dist/manifest.json` → 从 `dist/` 根部打 zip → `gh release create --prerelease --latest=false` 发布 nightly。
- 版本落点：Chrome 的 `manifest.version` 只接受 1–4 段整数（每段 0–65535），所以数字版本用 `<pkg>.<PR#>`（`0.6.6.105`，随 PR 单调递增、便于更新排序），完整串 `0.6.6.20261103-105` 写进 `version_name`（`chrome://extensions` 可见）并作为 release 标题/zip 名/tag（`nightly-20261103-105`）。job 内会校验版本格式，非法直接失败而不是发出装不上的包。
- 本地验证：用 dist 副本跑通「生成版本 → 改 manifest → 打包 → 校验」，并用 Playwright 加载改过的产物，`chrome.runtime.getManifest()` 返回 `0.6.6.105` / `version_name 0.6.6.20261103-105`。
