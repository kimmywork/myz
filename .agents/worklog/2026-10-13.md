## 2026-10-13T15:11:21+08:00

修复设备配对串在复制/粘贴途中被改写导致 `myz:pairingAccept` 抛 `InvalidCharacterError`（atob）的问题。

- 现象：新设备粘贴邀请串后 background 报 `Failed to execute 'atob' on 'WorkerGlobalScope': The string to be decoded is not correctly encoded`；源串为长度非 4 倍数的标准 base64（含 `+`/`/`/`=`），说明在浏览器生成之后、到达接收端之前被增删/改写了字符。
- 传输编码：`packages/sync-core/src/utils.ts` 新增 `bytesToBase64Url`（URL-safe、去 padding）；`pairingSession.encodePairing` 改用它，邀请串/响应串/配对串均不再携带 `+`/`/`/`=`。
- 容错解码：`base64ToBytes` 现接受标准与 URL-safe 两种字母表、忽略空白、padding 可省，并在长度不完整/含非法字符/atob 失败时抛出可读中文错误；`decodePairing` 捕获并包装为「内容无效或已损坏，请重新复制」，不再把裸 DOMException 抛给 UI；并校验解码结果非空对象。
- 测试：新增 `packages/sync-core/tests/utils.test.ts`（标准/URL-safe 往返、空白与缺省 padding、错误信息、payload 往返）；`pairingSession.test.ts` 增补 URL-safe 编码 + 旧标准 base64 兼容 + 截断串友好报错用例。
- 验证：sync-core `tests/utils.test.ts`+`pairing.test.ts` 8/8 通过（lint 0 error、tsc 0）；annotator `pairingSession.test.ts` 5/5 通过（eslint 0 error）。
- 说明：生成端（`btoa`）恒产出 4 倍数字符串，实测真实邀请串长度 328、mod 4 = 0，故非生成端缺陷；加固用于降低用户经聊天/剪贴板传递时的损坏概率并给出明确提示。
- 文件：`packages/sync-core/src/utils.ts`、`packages/sync-core/tests/utils.test.ts`、`myz-annotator/src/background/sync/v2/pairingSession.ts`、`myz-annotator/tests/unit/background/sync/pairingSession.test.ts`、两处 `AGENTS.md`。

## 2026-10-13T15:37:00+08:00

修复「批准失败：Device is already in the roster」——重复批准同一台设备时死锁。

- 现象：源设备批准过一次（设备已进 roster），若新设备导入配对串失败（如之前的串损坏）再重跑向导，第二次 `addDeviceToRoster` 直接抛「Device is already in the roster」，且异常发生在 `clearPending()` 之前，pending 一直不清、用户无法前进。
- 修复（`packages/sync-core/src/roster.ts`）：`addDeviceToRoster` 对「已在 roster 且未吊销」的设备改为幂等——校验 agreePub 一致后原样返回现有 roster（版本不递增、不重复写入）；对已吊销设备保留拒绝，但错误信息改为 `Device is revoked and cannot rejoin`。
- 语义：重新加入不需要先吊销；已登记设备重跑向导会拿到现有 roster（其 wrappedD 仍可解出 D）。真正被清空扩展数据的新设备会生成新 deviceId，按新设备正常加入。
- 注：`revokeDeviceAndRotate` 目前仅在 sync-core（含测试）中使用，`myz-annotator` 无吊销消息处理器与设备列表 UI，故 revoked 分支在应用层暂不可达。
- 测试：`packages/sync-core/tests/roster.test.ts` 新增「已激活设备重复批准幂等」「拒绝重新加入已吊销设备」两例；roster 7/7 通过，eslint 0 error。
- 文件：`packages/sync-core/src/roster.ts`、`packages/sync-core/tests/roster.test.ts`、`packages/sync-core/src/AGENTS.md`。

## 2026-10-13T18:38:00+08:00

修复加入账号后同步报「Rejected rollback to an older manifest version」——per-stream 状态未按账号隔离。

- 根因：`stream_state` 仅以 `streamId` 为键（`myz-annotator/src/background/sync/storage.ts`、`v2/stateStore.ts`），切/加入账号时不重置。设备带着上一个账号（或旧测试遗留）的 `streamVersion` 去拉新账号远端，`pullStream` 的 `assertNotRollback` 因「本地已见版本 > 远端 manifest 版本」直接拒绝（`packages/sync-core/src/stream/stream-pull.ts`）。
- 修复：`StreamStateRecord` 增加 `accountId`；`createStreamStateStore(accountId)` 在读取时若记录缺失或 `accountId` 不匹配（含旧版无 `accountId` 的遗留记录）即视为无状态，交给正常全量拉取；写入时带上当前 `accountId`。`v2/engine.ts` 传入 `account.accountId`。
- 迁移：旧记录无 `accountId` → 被视为陈旧忽略，下一次同步自动全量重拉并重写为新格式，无需手动清理；未推送的本地删除仍由 `collectTombstones` 单独携带，不受影响。
- 测试：新增 `tests/unit/background/sync/streamStateStore.test.ts`（同账号往返、跨账号忽略并覆盖、遗留记录忽略）。
- 验证：annotator background/sync 单测 28/28；`npm run build` green；`npx playwright test tests/extension/sync-mock-s3.spec.ts` 4/4 通过（含跨 profile 配对、加入、授权分支）。
