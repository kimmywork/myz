- 分屏（不丢上下文）：Chrome 155+ 的 Split View API（`chrome.tabs.createSplit` / `create({ splitWithTabId })`，`@types/chrome` 还没声明，代码里 `SplitViewTabs` + 运行时特性检测）让 DeepSeek 作为**第二个窗格**开在原页面旁边：没有会话时 `create({ url, splitWithTabId: sourceTabId })` 直接建在右侧分屏；已有会话时 `createSplit([source, existing])`（先 `tabs.move` 保证相邻）。分屏表达不了的情况（跨窗口、tab group/pin 状态不一致、任一已是窗格、源就是 DeepSeek 自己）回退到「激活标签页」，`canSplitWith`/`isSplitTogether` 把这套判定收敛成纯函数单测。
- **现状**：本机 Chrome 152（Electron）与 Playwright 的 Chrome for Testing 156 都还没有暴露 `createSplit`（连 `--enable-features=SplitView/ExtensionsSplitViewApi` 也没打开），所以 e2e 走的是回退分支并断言「chat 标签页被激活、源页不再激活」；等用户的 Chrome 升到带该 API 的版本，同一份代码会自动开分屏，无需改动。

## 2026-10-29T23:05:00+08:00

接入 Qwen（chat.qwen.ai）作为第二个「解读」provider，并实测两家站点的 DOM 约定。

- 实测（真实站点、已登录）：Qwen 输入框是 `textarea.message-input-textarea`（页面最大可见可编辑区，通用启发式直接命中）；写值同样需要原生 `value` setter + `input`；图片 `paste`（`DataTransfer` 携带 File）被页面消费并渲染 `img.user-img`（data: 缩略图，异步 1–2s），隐藏 `input[type=file]`（`accept=""`、`multiple`）可作回退；`button.send-button` 只在有内容时渲染。
- 路由：会话 `/c/:id`（另有 `/c/local`、`/c/guest`），新对话为根 `/`，登录页 `/auth?action=signin`（从 app bundle 的 `path:"/auth"` 与 `` `/c/${id}` `` 确认）→ `loginPath` 增加 `auth`，`isProviderNewChatUrl` 的根路径判定对 Qwen 同样成立。
- 模式：Qwen 没有 `aria-pressed` 推理开关，「选择模式/Select Mode」是随语言变化的工具菜单（联网搜索/深度研究/创作图片…），属于任务类型 → **不自动操作**，`thinkToggle` 保持只配 DeepSeek。原则：只依赖结构与路由，不依赖文案（同一账号实测过中英文两套 UI）。
- 稳定性改进：`findChatTab()` 改为「会话记录里的聊天页 → 当前激活 → 最新一个」，避免多个聊天标签页时跳到无关会话；e2e 每个用例自建并关闭自己的聊天页，消除用例间耦合。
- 测试：单测更新（两个 provider 均 `available`、Qwen `/auth` 登录页/`/c/:id`/根路径判定）→ 单测 341；e2e 新增 `qwen_provider_fills_its_own_chat_tab`（settings 切到 Qwen → 工具栏标签变「使用 Qwen 解读」→ 内容落进 Qwen 桩页、DeepSeek 桩页不受影响）→ 该文件 5 条全绿；vue-tsc / eslint / build 绿。
- 文档：新增 `docs/knowledges/ai-chat-integrations.md`（两家站点的路由/输入框/图片/模式开关/登录态事实与坑）。
