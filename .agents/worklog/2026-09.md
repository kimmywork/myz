## 2026-09-20T18:30:00

Fixed on-device translation only working once per page load.

- Root cause: `Translator.create({ signal })` was given the popover run's `AbortSignal`. Per the Translator/LanguageDetector spec, aborting the create signal after it fulfills has the same effect as `destroy()`, so closing the popover (or starting the next run) destroyed the cached per-pair translator; every later `translate()` rejected as aborted and the popover looked blocked. (Chrome also destroys the instance when the create signal aborts, so the detector was vulnerable to the same pattern.)
- Fix: `create()` is never passed a signal again — cancellation lives on the per-method `translate()`/`detect()` signals. The language detector is now created fresh per detect call and destroyed in `finally`, so a cancelled detection cannot poison later ones. `PrepareOptions` drops `signal`; aborted runs now surface "翻译已取消，请重试" instead of a blank error state.
- Tests: `tests/unit/reader/translate/browser-engine.test.ts` (3: create receives no signal, one translator per pair, fresh detector per call), plus e2e `pdf_translation_survives_repeated_open_and_close` (3 open/close cycles).

Verification: build, eslint, 168 annotator unit tests, PDF 27 e2e (headless).
