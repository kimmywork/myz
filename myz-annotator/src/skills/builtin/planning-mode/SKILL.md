## 目标

在主对话里完成复杂任务的规划、执行、修订和收尾，不依赖额外的规划子代理，避免上下文逐步漂移。

## 适用条件

- 用户请求包含多个步骤、依赖关系、探索和执行混合流程
- 任务需要跨页面、多次工具调用或阶段性推进
- 任务完成度需要你自行综合判断，而不是只输出一次性答案

## 规划原则

1. 先调用 `Task.get` 检查当前是否已有计划。
2. 没有计划，或目标已明显变化时，调用 `Task.init` 建立一份新的紧凑计划。
3. 计划必须短而可执行，通常 1-5 个任务即可。
4. 只有确有先后依赖时才设置 `blockedBy`。
5. 计划中优先写清任务标题、摘要、依赖和建议技能，不要堆砌冗余字段。

## 执行原则

1. 开始当前任务前，确认 `Task.get` 或现有上下文中的当前任务状态。
2. 需要浏览器操作时，优先读取 `/skills/browser-operations/SKILL.md`。
3. 真正需要工具时必须发起 tool call，不要只口头描述。
4. 每完成一个阶段，就用 `Task.update` 更新：
   - `status`
   - `summary`
   - `note` 或 `notes`
   - `outcome`
5. 任务全部完成后，用 `Task.complete_all` 写入计划级 `summary` 和 `outcome`。

## 审阅与修订

1. 发现计划过长、依赖错误、目标变化时，直接在主对话内重排计划。
2. 必要时重新调用 `Task.init` 覆盖旧计划，而不是维持一个失真的计划继续执行。
3. 若发现当前任务已不再适合继续，先 `Task.update` 记录原因，再切换当前任务。

## 向用户提问的边界

只有在以下情况才提问：

- 缺少账号、权限或外部确认
- 存在潜在破坏性操作
- 目标存在互斥决策，无法自行合理假设

提问前必须先输出：

`[REQUIRE_USER_INPUT]`

## 推荐流程

1. `Task.get`
2. 需要时 `Read /skills/planning-mode/SKILL.md`
3. 需要时 `Task.init`
4. 执行当前任务
5. 用 `Task.update` 持续更新
6. 完成后 `Task.complete_all`
